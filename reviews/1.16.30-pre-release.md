# Pre-release triage: 1.16.30 (base v1.16.29, patch, depth=full)

**Owner needs to read:** no blocker, no deferred major and no gate left undone. Two scope items need your decision:
1. **The 24h key is not what the code does.** The session a key buys lasts 24h (`GLOBAL_KEY_SESSION_TTL_MS`), but `globalKeyRefresh` now renews a dead or expired session from the key cookie on any same-origin request. The key cookie itself lasts **30 days** (`GLOBAL_KEY_COOKIE_MAX_AGE_S`, dev-auth.ts:431). So a key holder is in practice cut off only when the cookie expires (30d) or the key is rotated and the servers restarted. The 24h no longer ends anything for them. If you meant "access ends after 24h", the cookie Max-Age has to drop to 24h. If you meant "each session lasts 24h, but restarts don't matter", the code is right and only the docs need fixing.
2. **Only global-key holders are fixed.** Sessions opened with a plain `--link` / `--link --share` invite (no key cookie) still die on every `bun --watch` restart, including one triggered by an example edit. A save after that still fails with "needs an invite link". Decide whether that is in scope for this release or a follow-up.

## Findings

### Minor
- **[correctness, verified] After a restart, the haltija bridge WebSocket over the tunnel stays locked out.** `src/doc-system/site/dev-auth.ts:1255`. `globalKeyRefresh` returns null for any `upgrade` request, so `haltijaBridgeAdmission` refuses the dead session (404). Every reconnect fails the same way until some other same-origin fetch, or a reload, renews the cookie. The code comment's reason ("an upgrade has no response to carry the cookie") does not hold: `srv.upgrade(req, { headers })` can set a cookie on the 101 response. This is not a regression from 1.16.29, but it is the user's "restart resets everything" symptom on the agent-driving channel. Fix: renew on upgrade, keeping the same evidence rule (browsers send `Origin` / `Sec-Fetch-Site` on WebSocket handshakes). Otherwise, document that the bridge needs a reload after a restart.
- **[docs] (unverified) "What it costs" gives 30d and 7d session lifetimes and never mentions the 24h key session or renewal.** `src/doc-system/doc-site-system.md:~1153`. "Sessions live in memory, so the restart ends them all" is no longer true for key holders. State it plainly: a key opens a 24h session that is renewed from the cookie on page load or on a same-origin request (after a restart too), so a key holder is cut off only by key rotation plus a restart or by cookie expiry (30d). Pin the figure with a test against `GLOBAL_KEY_SESSION_TTL_MS`. Settle owner item 1 first.

### Nit
- **[correctness] (unverified) A burst of concurrent requests after a restart mints one session and one log line per request.** `dev-server.ts:2049`. This is bounded by MAX_SESSIONS=1000 with oldest-first eviction, so the harm is log noise plus some pressure on other readers' sessions. It also conflicts with the output-hygiene rule. Log once per burst or per boot.
- **[security] (unverified) The MAX_SESSIONS rationale is stale.** `dev-auth.ts:1104`. The comment says "one per page load"; it can now be one per in-flight request from a page left open across a restart.
- **[security] (unverified) Tests do not cover `Sec-Fetch-Site: cross-site`, `none`, or `Origin: null`.** `dev-auth.test.ts:1735`. All three are refused today by strict equality, but nothing pins that, and `Origin: null` is the one value an attacker can choose. Add three expectations.
- **[blast-radius] (unverified) A second same-origin predicate sits beside `isSameOriginRequest`.** `dev-auth.ts:1255` vs `:837`. Its stricter semantics are deliberate. Share a helper with a `requireEvidence` mode, or cross-reference the two docblocks.
- **[docs] (unverified) The CHANGELOG entry does not state the evidence rule.** `CHANGELOG.md:7`. Add one sentence: renewal applies only to non-navigation requests proving the workspace's own origin, and never to WebSocket upgrades. That answers release-check's "say what moved" warning, and tells a scripted (no-header) client why it still gets 401.
