## Fix before the tag (confirmed minors, recommended, each small)

These are not majors, so they are not mandatory. Each is confirmed and cheap to fix, and two of them make a shipped promise wrong.

- [ ] **The SPA fallback's `<base href="/">` sends in-page `#` links to the root document.** Confirmed. In `src/doc-system/site/dev-server.ts:405`, `withRootBase` is applied whenever `asRoot` is set (around line 1453). `docFilenameForHref` returns null for `#` hrefs (`src/doc-browser.ts:606`), so the browser follows them itself and resolves them against `/`. Footnotes (`#fn-N`), back-references and `[x](#heading)` links on a fallback-served page such as `/guide/` reload the home doc. This only affects the dev server; the built site is unaffected. **Fix:** stop injecting a document-wide `<base>` and rewrite only the root page's relative `<script>`/`<link>` URLs to root-relative ones. The alternative is to have the doc-browser handle `#` clicks itself. **Check:** add a step to `tests/project-dev-server.pw.ts` that clicks an in-page `#` link on `/guide/` and asserts the pathname stays `/guide/`. The step must fail with the current `<base>` in place.
- [ ] **Overlapping `commit:true` saves to the same file record the wrong versions.** Confirmed. In `src/doc-system/site/data-store.ts:309`, `writeDataFile` runs outside `commitQueue` (dev-server.ts ~1161), so save B can overwrite the file before save A's queued `git add` runs. Commit 1 then carries A's attribution with B's content. Commit 2 returns `null`, which the client documents as "nothing changed". The final file is correct, but one version and its attribution are lost from `?history` and `?at`. **Fix:** do the write and the add/commit in one queued step whenever `commit` is on. **Check:** a `data-store.test.ts` case that sends two concurrent saves of one file with different content and asserts two commits, where `git show <hash>:<file>` for each matches its own save.
- [ ] **`commit:true` commits into the developer's in-progress rebase, bisect or detached HEAD.** Confirmed by a scratch-repo reproduction. `commitDataFile` (`src/doc-system/site/data-store.ts:283`) never checks repository state. In the reproduction, with `git rebase -i` stopped at an `edit`, a save committed into the rebase, and `git rebase --abort` then discarded both the commit and the file on disk. The success response still carried a commit hash. **Fix:** before committing, check for a detached HEAD (`git symbolic-ref -q HEAD` fails) and for `rebase-merge`, `rebase-apply` or `BISECT_LOG` via `git rev-parse --git-path`. In any of those states, write the file, skip the commit, and return `commitError` naming the state. Document this next to "Other staged work is left alone". **Check:** a `data-store.test.ts` case with a detached HEAD and one with a stopped rebase, each asserting that no commit happens and that `commitError` is set.

- [ ] (unverified, nit) The editableData config-name deny-list misses tool configs that can run commands (`project.json`, `turbo.json`, `nx.json`, `lerna.json`, `composer.json`, `Cargo.toml`, `pyproject.toml`, `firebase.json`, `vercel.json`, `netlify.toml`, `wrangler.toml`) at `src/doc-system/site/data-store.ts:60`, while `site-config.ts` says config names are "never written". **Blast radius and efficiency**
- [ ] (unverified) The 20s git timeout calls SIGTERM on git only, so a slow pre-commit hook's children (tsc, eslint, bun test) keep running, and each save adds more of them in a dev server that runs for days (`data-store.ts:249`). Spawn git in its own process group and signal the group, and/or add an opt-out such as `hooks: false` that passes `--no-verify`. Document the timeout, and have `commitError` say when it fired.
- [ ] (unverified) Each `commit:true` save runs four git processes in sequence plus the repo's hooks, the POST waits for all of them, and the queue has no limit (`data-store.ts:484`). State in the JSDoc and doc-site-system.md that this mode does not suit autosave. Measure one hooked commit on a real project before deciding whether to coalesce saves.
- [ ] (unverified) The git-backed tests inherit the developer's global git config. Global `core.hooksPath` makes the "a commit that fails rejects" test fail locally, though not in CI (`data-store.test.ts:28`, `project-dev-server.pw.ts`). Set `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`, or set `core.hooksPath=.git/hooks` in each temp repo.
- [ ] (unverified, nit) Reader-facing hints still recommend `trustLan: true` (`src/doc-browser.ts:1595`, `:1611`, `src/live-example/component.ts:2486`). Point them at a named network or `TOSIJS_TRUST_LAN=1` instead, and keep the text in one shared constant.

**Docs and coverage**

Not checked: the `home` doc with README moved to `/readme/`, query routing on a deployed `index.html`, and host-level SPA rewrites (Firebase, GitHub Pages). The CHANGELOG should also say the relative-asset fix applies only to the dev server.
- [ ] **New public surface is not covered by the consumer lane:** `tosijs-ui/doc-system/data-client` (via the `./*` wildcard), `EditableDataOptions` and `DATA_EXTENSIONS` are not in `bin/smoke-consumer.ts`. The hard-coded `/__docstore/data` endpoint has not been checked from outside the repo.

Unit tests claim coverage for IPv4-mapped IPv6 peers (`::ffff:192.168.x.x`) matching an IPv4 CIDR, but this was not confirmed against a live dual-stack Bun listener.

Spawning child processes is the sanctioned pattern, but RSS over repeated saves was not measured under the dev-server memory rules.
- [ ] **Playwright lane wall-clock:** not measured after adding `project-dev-server.pw.ts` and the per-request route handler in `tests/fixtures.ts`.
