## Blockers

### B1. A file inset reads any file under the project root and publishes it (security, confirmed)

`single-source.ts:219-228`. The only guard is `abs.startsWith(root + path.sep)`. There is no check on extension, directory, dotfiles or `docPaths`, and no realpath.

- **Reproduced:** `<!--{ "inset": "../.env" }-->` in `docs/page.md` builds green with `API_KEY=abc` in the page text. A symlink inside the project that points outside it is also read.
- **Why it blocks:** `dev-server.ts:979` and `:1016` gate `/__docstore/source` read and write on `mayEditSource(resolved, allowedSources())`. The comment there says this is so a tunnel invitee cannot read `.env`-adjacent files (#128). A write-session invitee can now add the directive to a page they are allowed to edit. The watcher rebuilds, and the file's text is served in the page, `docs.json` and `llms.txt`, including to read-only visitors.
- **Limits:** it needs a write session. The new exposure is mainly for markdown-only adopters, since a write invitee on a site that scrapes `.ts` can already edit code. The end-to-end tunnel flow was not run live; each link was read in code.
- **Fix:** restrict the file fallback to markdown files under a configured `docPaths` root, with no dot-prefixed or ignored path segment, and check containment on `fs.realpathSync(abs)` as well. Reuse `isUnderRoot` from `dev-server.ts`.
- **Tests to add:** `../.env`, a non-markdown target, a symlink out of the root, a path into `.git` or `node_modules`.

### B2. A hidden or draft document can be inset, against the documented guarantee (security, correctness and docs, each confirmed independently)

Same branch. `withoutHidden` drops the doc from the corpus, so `resolveParent` misses and the code falls through to reading the same file from disk. The frontmatter strip removes `draft: true`, and `bodyOf` removes the `{"hidden": true}` block.

- **Reproduced three times:** the host page's text contains the withheld body, with no error.
- **The promise it breaks:** `/Users/tonioloewald/tosijs-ui/src/doc-system/doc-site-system.md:1239-1240` says "A hidden document cannot be inset, so insetting never publishes something that was withheld." `docs.ts:646-649` says the same. The page is published to the site, the ePub and `llms.txt`.
- **Trigger:** the ref is a filename relative to the host, which is the form the docs' own examples use.
- **Same class:** a doc excluded by `ignore` (the default `reviews` exclusion) is insettable by relative path. The verifier showed `../reviews/r.md` insets, but did not isolate the default-ignore case.
- **Fix:** pass the pre-filter set (hidden source paths, descendants of hidden docs, the ignore list) into `assembleCorpus`, and throw `SingleSourceError` when a file inset resolves to a withheld path.
- **Tests to add, through `extractDocs`:** frontmatter `draft`, JSON `hidden`, a descendant of a hidden parent, an ignored directory.

**Re-review scope after remediation:** security and correctness over the remediation diff, plus the `/__docstore/source` handlers.

## Major follow-ups (confirmed, not blocking)

### M1. A real `tjs` console prints `undefined` or a prelude function for some lines (correctness and blast-radius)

`/Users/tonioloewald/tosijs-ui/src/live-example/component.ts:1486` and `:1752-1772`. The tjs transform emits a multi-statement prelude before the user's expression, and the evaluators assume a single expression.

| Line typed (with `x = 5`) | Path | Prints | Correct |
|---|---|---|---|
| `x == '5'` | direct-eval hook | `false` | yes |
| `x == '5'` | non-hook fallback | `undefined` | no |
| `(await Promise.resolve(5)) == '5'` | hook | `undefined` | no |
| `const z = x == '5'` | hook | the `__tjs.toBool` function | no |

- The headline case works. The failures are silent wrong answers.
- The tests use stand-in dialects with no prelude, so the real transform is never exercised.
- `ts` was not verified, and nothing was run in a browser.
- Minimum for this release: state the limit in the CHANGELOG next to the claim and add a test against the real tjs transform. A proper fix needs a completion-value-preserving async eval, or a separable prelude from tjs-lang.

### M2. Print and ePub arrange "the book" differently (blast-radius and correctness)

`/Users/tonioloewald/tosijs-ui/src/doc-system/book-html.ts:183`, called from `doc-system.ts:381`. The ePub runs `partitionByBook` → `placeInBook` → `selectBookDocs`. Print only filters hidden docs, but now takes `bookText`.

- **Reproduced:** Print shows the site outline and order, the book wording, and includes `book: none` pages.
- `doc-site-system.md:1253` promises Print "the book wording" and does not say placement stops at the ePub.
- Either extract one `arrangeForBook()` used by both paths, or record a keep-decision on the board and add the doc sentence.

### M3. A directive inside a list item or blockquote is silently ignored (docs confirmed; correctness reported it as a minor)

`single-source.ts:52`. Only top-level `html` tokens are visited.

- **Reproduced:** an inset of a non-existent file inside a list item builds green and ships the raw comment. An unclosed `only` inside a blockquote is accepted.
- `doc-site-system.md:1203-1206` promises that a mistake "fails the build instead of leaving a page quietly short".
- Fix: walk nested tokens and throw for any unresolved directive. At minimum, correct the doc sentence.

- **Whole-page editor.** Only the live-example save got a single-source guard. Nobody confirmed that the doc-browser page editor (`doc-browser.ts` ~1430-1516) and `example-store.ts` write raw source and not assembled `doc.text`. - **`bookText` in the shipped corpus.** Payload size is unmeasured. Search, `llms.txt`, markdownPages and the truncated-doc guard were not checked against it. The `metadata()` change has no regression test for a doc whose real metadata contains an `only`, `end` or `inset` key.
