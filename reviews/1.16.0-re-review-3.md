## Majors: fix before tagging

1. **The release gate is red for 1.16.0** (correctness, verified). `CHANGELOG.md` around line 41.
   - Running `bun bin/release-notes.ts --check --version=1.16.0` exits 1.
   - The cause is the `[fix] 32 unused Component / WebComponent imports` bullet in `0e2de5bc`, which appears nowhere in `## 1.16.0`.

   - The commit's "all four lanes green" claim does not cover release-check.
   - **Fix:** those imports were introduced and removed within the same unreleased release, so adopters never saw them. Re-tag the bullet `[note]` in a follow-up commit (the CLAUDE.md loop rule applies), or write it into the section. Then re-run `release-check --version=1.16.0` and require exit 0. Re-review scope: Tier 0 only.

2. **The markdown exclusion lives only in `tosijs-format`'s argv, and the reason given for that is wrong** (blast-radius, verified). `bin/format.ts:8-11`, `:82`.
   - **What still reformats markdown in adopter repos:** editor format-on-save, lint-staged/husky hooks and a bare `prettier --write`. None of them go through the bin.
   - **The config route works:** with Prettier 2.8.8, `overrides: [{ files: '*.md', options: { requirePragma: true } }]` leaves `.md` byte-identical under `--check`, `--write .` and `--stdin-filepath x.md` (the path editors use).
   - **Where the wrong "Prettier 2 cannot exclude a glob / share an ignore" claim appears:** the bin/format.ts header, the 1.16.0 CHANGELOG entry and `../tosijs-coding-practices/practices/code-quality.md:38`.
   - **Fix:**
     - Add the override to `.prettierrc.json` (the house config).
     - Correct the rationale in bin/format.ts and the CHANGELOG.
     - Keep `tosijs-format` as a convenience.
     - The practices-doc correction is routed below.
