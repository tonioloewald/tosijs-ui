## Minor

### M1. The widened doc-browser same-page identity is not pinned by a test (unverified)
- **Lens:** correctness (coverage gap) · `src/doc-browser.ts:1283`
- **Problem:** `go()` now treats a click as same-page when `filename === app.currentDoc.filename` and the hash is empty. Before, it compared the raw pathname and search. The new Playwright step (`/menu/#somewhere` → `/menu/` pushes) pins the hash rule. The original #174 step (`/carousel/` → `/carousel/`) passes under both the old and new code. Nothing exercises the cases the CHANGELOG now claims:
  - `/carousel` or `/carousel/index.html`, then clicking `/carousel/`, should replace.
  - In query mode (the default routing), `?x&_testMode=1`, then clicking `?x`, should replace.
- **Impact:** If someone later reverts to a raw-path compare, every lane still passes and the documented behaviour quietly regresses. The reviewer read the code and found the logic correct today (`filenameFromLocation` goes through `slugForPath` and the query `split('&')[0]`). The behaviour is correct but unpinned.
- **Fix:** Add a `tests/doc-system.pw.ts` case: go to `/carousel/index.html`, click `/carousel/`, and assert `history.length` is unchanged. Add a query-mode case too, either as a Playwright page or a happy-dom unit test of `createDocBrowser({ routing: 'query' })`.

### M2. Router `navigate()` keeps its own raw-string copy of the #174 policy, with a different identity rule (unverified; merges a correctness nit and a blast-radius minor)
- **Lens:** blast-radius (minor) + correctness (nit) · `src/router.ts:334-336`
- **Problem:** The rule "a navigation to where you already are replaces, unless a hash is in play" now lives in two places:
  - `doc-browser.ts:1283` compares by document.
  - `router.ts:334` compares `href === pathname + search` as raw strings.
- **Impact:** The two copies have already diverged.
  - On `/search/caf%C3%A9`, calling `navigate('/search/café')` pushes a duplicate entry. The same happens for `navigate('/a b')`, and for `navigate('/a/')` while on `/a` when the route matches both. Each time, Back appears dead, which is the exact #174 symptom, now for router adopters.
  - A future fix to one copy will reach only one audience: doc-site readers or router apps.
  - The earlier 1.16.6 triage recommended a shared `pushOrReplace(href)`. The remediation fixed both bugs but did not consolidate them, and nothing records keeping them apart on purpose.
- **Fix, either of:**
  - **(a)** Normalise before comparing, e.g. `const u = new URL(href, location.href); same = location.hash === '' && u.pathname === location.pathname && u.search === location.search`. Optionally move the push-or-replace decision into one shared helper, with each caller supplying its own idea of "same" (route vs document).
  - **(b)** Add keep-decision comments at both sites, each pointing at the other and saying why the identity rules differ.
- **Test:** Add a `router-history.test.ts` case with a space or non-ASCII path.
- **Severity:** Not a blocker for a patch. Router adopters had this behaviour before 1.16.6 anyway, and this release improves the common case.
