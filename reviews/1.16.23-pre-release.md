## Minors

1. **(correctness + blast-radius, verified)** `<tosi-select options>`, `<tosi-segmented choices>` and segmented's `other` all split their `caption:icon` strings on every `:`. An explicit rule name is therefore cut down to the rule's prefix icon, and nothing warns about it.
   - **Where:** `src/select.ts:374` (`parseOptionsString`), `src/segmented.ts:199-203` (`parseChoicesString`) and `src/segmented.ts:426` (`this.other.split(':')`).
   - **Reproduced:** `parseOptionsString('done=Done:check:square')` returns `{caption:'Done', icon:'check'}`, and the plain check icon is drawn.
   - **Why it matters:** this diff fixed the same collision in its own demo, where `icons/icon-composition.md` now splits on the first `:`. The shipped components that use the same grammar were not changed. They are where an adopter is most likely to write the new syntax.
   - **Not a regression:** strings without a second `:` behave as before. The workaround is to pass object options or choices.

## Nits

2. **(correctness, unverified, sanity-check before acting)** The docs say "The explicit form always applies the rule." That is not true when an icon is registered under the exact colon name, because `defineIcons({'check:foo': svg})` wins. `readsAsRule` does not warn either, since it tests `/[A-Z]/` against the character after the prefix, which here is `:`.
