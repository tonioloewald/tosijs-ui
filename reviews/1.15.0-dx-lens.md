## Blockers (must clear before `git tag`)

### B1 — `save-to-source` still uses the OLD "which fences are examples" rule, so an edit is silently saved over the wrong fence
`src/live-example/save-to-source.ts:22` · lens dryness · **verified, and independently reproduced during triage**

`example-policy.ts` shipped this release as "THE ONE RULE", and `insertExamples` (`insert-examples.ts:131`) now filters through `isLiveFence`. Its structural twin was not updated: `EXECUTABLE` (`save-to-source.ts:22`) is still a flat six-language set, `groupExamples` counts every executable fence toward ordinals, and `findFencedBlocks`' regex `^([ \t]*)```([\w-]*)[^\n]*` stops at the colon so it cannot even see `:static`.

Reproduced by executing the real modules against one document:

```
src:  ```js:static  (illustration)   then   ```js  (live)
save-to-source groups: 2   →  group[0] body = "const notRun = 1"   ← the :static block
isLiveFence('js','static','auto') → false   →  insertExamples makes ONE example, ordinal 0 = the LIVE block
rewriteExampleBlocks(src, 0, {js:'const EDITED = 99'})
  →  the :static illustration now reads `const EDITED = 99`; the live block is untouched
```

`LiveExample.saveToSource` (`component.ts:1044`) passes `data-example-ordinal` straight through. The "Couldn't locate this example" alert only fires when `ordinal >= groups.length`; here group 0 exists, so it POSTs **silently**. Under `liveExamples: 'opt-in'` every ordinal shifts, so every save on a prose/book site writes into a different block than the one edited.

*In-repo exposure today is nil* — the corpus has no real `:static` fences and our policy is `auto` — but this is silent corruption of the author's own source file, in the dev/tunnel authoring flow the project calls its killer feature, triggered by a feature introduced in this very release.

**Fix:** widen the info-string capture in `findFencedBlocks` to keep `:mode`; have `groupExamples` filter with `isLiveFence(lang, mode, policy)` and delete the local `EXECUTABLE`; thread `examplePolicy()` in from `component.ts` at save time. Add a unit test that a doc with a `:static` fence ahead of a live one round-trips ordinal 0 to the live block. **Fix F1 (ePub) in the same pass — same root cause, three copies of one rule.**
*Re-review scope: correctness + blast radius over the remediation diff only, plus confirmation that `save-to-source.test.ts`'s existing ordinal fixtures still pass unchanged.*

### F1 — The ePub "Run this example live" links are a third, unsynchronised copy of the same rule
`src/doc-system/site/epub.ts:217` · dryness · **verified** — *fix alongside B1*

`EXAMPLE_LANGS` is a verbatim third copy of the six-language set, and `injectExampleLinks` (`:286-311`) re-implements grouping and the `example-${ordinal+1}` id rule without consulting `isLiveFence` or `config.liveExamples` (`liveExamples` appears nowhere in `epub.ts`). Reproduced by the verifier: with a `js:static` fence the ePub emits a spurious "▶ Run this example live ↗" above a block with no live example, and every later link is off by one with `#example-3` pointing at a non-existent anchor. Under `liveExamples: 'opt-in'` — the setting the config docs recommend **for book sites**, i.e. exactly who builds an ePub — the page produces zero live examples while the ePub still injects live-run links to all of them: every link in the shipped book is dead. The one existing test (`epub.test.ts:178`) asserts only that the class is present.

### F2 — `<tosi-table>`'s published selection docs describe pre-1.15 behaviour
`src/data-table.ts:460` · docs · **verified**

The `/*#` block (published at `/data-table/`, verbatim in `docs/data-table/index.html`) still says `selectRow`/`selectRows` are "used internally by the selection code". After this release: single-select `selectRows([a,b,c], true)` **replaces** the selection, keeps the last row and `console.warn`s (`:2775-2790`); and both methods now fire `selectionChanged` unconditionally (`:2793`). The re-entrancy is not hypothetical — `src/crud.ts:687` needed a `_applyingSelection` guard because the deselect half reported an empty selection and cleared the record mid-edit. The new contract exists only in the CHANGELOG, which is unpublished. *(Sub-claim (a) is overstated: `deSelect()` still calls `selectRows`, so it is the click path that stopped using them.)*

### F3 — The #152 hash-only popstate guard has no test at any tier, and its failure mode is a silent no-op
`src/doc-browser.ts:834` · coverage · **verified**

The guard's own comment records that dropping the `String()` coercion compares a BoxedScalar to a string and "silently do[es] nothing" — falling back to a full `innerHTML` re-render, i.e. the reported defect (editor loses focus and buffer mid-keystroke). Nothing observes it: `doc-browser.test.ts` covers only `hasTestBlock`; `coverage.test.ts` uses `routing: 'memory'`, where the listener is never registered; every Playwright `goBack()` is either cross-document or asserts hash/value only after **re-querying** the element, which a fresh re-rendered node satisfies. The commit that added this guard mutation-verified its two sibling fixes and not this one. *(Closing it at the unit tier needs `location` added to `test-setup.ts` first — the cheap close today is a Playwright assertion that a node inside `.doc-content` is still attached across a hash-only back.)*

### F4 — `<tosi-highlight>` ships no token palette, so the standalone use it is sold for renders colourless
`src/highlight-block.ts:75` · dx · **verified, reproduced in a browser**

`lightStyleSpec` is `{ 'tosi-highlight': { display: 'block' } }` and nothing else; `find dist -name '*.css'` returns **nothing**, so no palette ships in the package. Served with only `dist/iife.js`, a `<tosi-highlight>` produced 17 correct token spans all computing to `rgb(0,0,0)`. The `.token.*` rules exist only inside `docSystemStyleSpec()` (which drags the whole doc-site chrome) and `DEFAULT_BOOK_CSS` (exported from the Bun-only `tosijs-ui/site`, and it restyles body/headings/tables). *Partial mitigation:* the doc block does say "style `.token.keyword` … yourself, or import the doc-system CSS" — but the second half names an import that does not exist. Fix by extracting an exported `highlightStyleSpec` (the rules are already all `varDefault`) and naming the real import in the Styling section.
