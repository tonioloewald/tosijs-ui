### B2. Library code reads its own deprecated aliases (blast-radius rated it blocker; correctness and docs rated it major; all verified)
- **Site 1 (the blocker): `src/select.ts:232/717/728`.** The file imports `XinLocalized` and reads `XinLocalized.allInstances` in connect and disconnect. Since 4aae91bf2, `XinLocalized` is a `deprecatedClass` Proxy whose `get` trap warns on every read.
  - **Probe:** `document.body.append(tosiSelect({ localized: true, options: 'a,b' }))` logs "XinLocalized is deprecated: use TosiLocalized. tosijs-ui 1.21.0 removes it."
  - **Where it ships:** `dist/select.js` and `dist/iife.js`. The select page's own Localization example triggers it too.
  - **Why the documented remedy fails:** migrating.md's "search your code for Xin[A-Z]" finds nothing in the consumer's code.
  - **1.21.0 hazard:** deleting the alias breaks select.ts.
  - **Precedent:** this is the class CLAUDE.md records as tosijs#31, the reason a peer floor was raised.
- **Site 2 (same class, minor on its own): `src/live-example/execution.ts:61`.** `registerComponentsInIframe` reads `.tagName` on every export, so the 15 class Proxies log 15 warnings on the first `:iframe`/`:ide` example of each page load. It was measured by calling the real function with the root namespace. Nothing in this repo's corpus, or in the ~19 sibling repos checked, uses those modes today.
- **Fix:**
  1. In select.ts, use `TosiLocalized` and drop `XinLocalized` from the import.
  2. Make the iframe scan skip aliases. Have deprecated-alias.ts keep a WeakSet of its Proxies and export `isDeprecatedAlias()` (`WeakSet.has` fires no trap), or exempt `tagName` from the warning.
- **Clears when:** one guard test covers the whole class:
  - (a) a source-parse test, shaped like `on-event-members.test.ts`, fails on any read of the 33 alias names outside their own export lines;
  - (b) a test mounts `tosiSelect({ localized: true })`, runs `registerComponentsInIframe` over the root namespace, and asserts zero "is deprecated" lines.
  - Both must fail on HEAD.

## Fix before the tag (verified majors; no re-review needed)

- [ ] **M1. Subclassing an `Xin*` class alias builds the base element** (correctness and security lenses, verified with a control). File: `src/deprecated-alias.ts:41`.
  - **Cause:** the `get` trap ignores the receiver and returns `value.bind(target)`.
  - **Effect:** `class MyForm extends XinForm { static preferredTagName = 'my-form-sub' }`, then `MyForm.elementCreator()()`, gives a TOSI-FORM without the subclass's members, and `my-form-sub` is never registered. `tosiForm() instanceof MyForm` is true. XinRating and XinTag behave the same way.
  - **Regression:** this worked in 1.19.2, where `XinForm === TosiForm`. The `[change]` bullet's "keeps working" claim is false for subclasses.
  - **Fix:** take `receiver`; use `Reflect.get(target, key, receiver)`; bind functions to `receiver === alias ? target : receiver`.
  - **Check:** in `deprecated-alias.test.ts`, for each of the 15 class aliases, subclass it with its own tag and an own method. Assert `Sub.elementCreator()()` carries the subclass tag and method, and that the survivor's element is not `instanceof Sub`. The test must fail with the current trap.
  - **Related note from triage (JS semantics, not separately probed):** a Proxy is never `===` its target. `XinForm === TosiForm` is now false where 1.19.2 had it true. Say so in migrating.md rather than claiming "keeps working" without qualification.

- [ ] **M2. A footnote definition between two fences still makes save-to-source write into the wrong example** (correctness lens, verified). File: `src/doc-system/code-fences.ts:38`.
  - **Cause:** the page's `footnoteDef` extension renders nothing, so `insertExamples` groups the blocks on either side. Plain `marked.lexer` reads `[^1]: a note` as a paragraph, so `lexCodeTokens` splits them.
  - **Effect:** an edit to the page's example 2 blanks `const a = 1` out of a different example, and the edit itself is written nowhere.
  - **Fix:** lex with the page's own Marked instance (`docMarked`, extensions included), and treat any token that renders empty as rendering no element. Or derive `followsCode` from rendering the doc, so a future extension cannot drift. If convenient, fold in the unverified indented-closer minor in the same file: accept a closing fence indented 0 to 3 spaces only.
  - **Check:**
    - A save-to-source test with the repro source (html, then `[^1]: a note`, then js, then prose, then html) yields 2 groups that match `insertExamples`. Rewriting ordinal 1 changes `<p>B</p>` and leaves `const a = 1` intact. It must fail on HEAD.
    - Also run the "example ordinals match the page" oracle on each doc's raw `doc.path` with `file` passed, which is the path a save actually takes.

- [ ] **M3. The `createDocBrowser()` 'memory' default is documented as URL-only, but it turns off much more** (docs lens, verified). Files: `src/docs/migrating.md:27`, the doc-browser options paragraph, and the `[break]` bullet.
  - **What memory routing also disables:**
    - `window.__docTestResults` (`doc-browser.ts` l.840);
    - the background test runner (l.2842);
    - `role="main"` (l.2265);
    - back/forward (l.1161).
  - **Who is hit:** a whole-page testbed built from the page's own Quick Start, with CI that awaits `__docTestResults`, hangs after the upgrade.
  - **Fix:** list all five effects in migrating.md, the CHANGELOG `[break]` and the options paragraph. Say that a whole-page testbed should pass `routing: 'query'` (or `'path'`). Add `routing` to the Quick Start or a sentence about it.
  - **Check:** read the three surfaces and confirm they name all five effects. Add a unit test asserting that memory mode sets no `window.__docTestResults` and starts no runner, so the documented list is pinned.

- [ ] **M4 (the part fixable now). The security entries name affected ranges** (security lens, verified). This is folded into B1. The 1.20.0 Security entry must name:
  - **Tooltip `title` → innerHTML:** 1.4.9 to 1.19.2. The bug arrived in 2e7ff6e4a; 1.4.9 is on npm, although the first git tag is v1.5.0. `initTooltips()` converts every title by default. CWE-79. Mitigation for anyone who cannot upgrade yet: `initTooltips({ convertTitles: false })`, and keep untrusted text out of `data-tooltip`.
  - **Default `text/html` drop → innerHTML:** xinjs-ui 0.8.0 to tosijs-ui 1.19.2.
  - **Checklist store deleting before its ownership check:** 1.19.0 to 1.19.2. Dev only.
  - **Unbounded dev-server request bodies:** every release with the dev server. Dev only.
  - **Check:** the docs glance in the B1 re-review.
