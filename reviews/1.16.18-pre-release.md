## Blockers

### B1: The icons-page live example fails its own inline test (docs, **verified**)
`src/icons.ts:505`.

- **What happens:** `spin120Loader40s_30x$cloud` resolves to `SPAN.tosi-icon-composite > [svg, SPAN.tosi-icon-composite(loader40s_30x) > svg]`. The spin layer is wrapped in its own composite.
- **Why the test fails:** `preview.querySelectorAll('.tosi-icon-composite')` returns 4 elements, not 3, and the inner one holds 1 svg, not 2.
- **Evidence:** `.browser-tests.json` (15:40, after HEAD) records 83 passed and 1 failed: `Expected 4 to be 3 | expect(composites.length).toBe(3) (line 3)`. The verifier reproduced it in happy-dom, with svg counts [2,1,2,2].
- **Impact:** `tests/doc-tests.pw.ts` requires the doc tier to be failure-free and runs in CI's e2e job, so CI goes red. Readers also see a failing badge on the example the CHANGELOG says is "checked on every build".
- **Scope:** the icon fix itself is correct. The defect is only in the example's assertion.

**Fix:**
- Count top-level composites only: `preview.querySelectorAll(':scope > .tosi-icon-composite')`, or iterate `preview.children`.
- Assert each of those has at least 2 svgs.
- Optionally, also assert that no square-placeholder svg is present, which is the property #224 is actually about.

**Clears when:** `bun playwright test tests/doc-tests.pw.ts --project=chromium` is green with the icons page recorded. Re-review scope: Tier 0 plus that lane run.
