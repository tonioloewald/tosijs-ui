## Fix before the tag

- [ ] **Major (verified, correctness): a custom `editor` is silently not mounted on a property the schema describes but the form has no built-in control for.** `src/schema-form.ts:1961`
  - The guard `nodes.some(n => n.path === path && n.kind !== 'unsupported')` also matches real schema nodes of kind `unsupported` (untyped `{}`, `type: 'null'`, `prefixItems` tuples, mixed unions), not only the unknown-path placeholder.
  - Reproduced at HEAD: with editors on `name`, `meta: {}`, a tuple and a null property, only `[data-plugin="name"]` mounts. The others show "no control for type …" and nothing is warned.
  - At base the editor mounted unconditionally (read from the diff, not executed). This contradicts `buildNode`'s own rule at lines 1270-1274, and a `format` plugin on the same node still mounts.
  - Fix: key the refusal on the `unknown` list that `curateNodes` already returns (`!unknown.includes(path) && nodes.some(n => n.path === path)`).
  - **Clearing check:** a unit case next to the existing unknown-path test, asserting `[data-plugin="meta"]` exists for an editor on an untyped property (and ideally tuple and null). It must fail with the fix reverted, and the unknown-path case must still keep its placeholder and warning.
