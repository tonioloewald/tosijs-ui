## Fix before the tag

All four are verified majors. Each is cleared by the listed check; no re-review needed.

- [ ] **A function `editor` silently drops an edit after an external value change** (`src/schema-form/curate.ts:124`, correctness, verified by reproduction).
  - `commit` dedupes against `last`, which `sync` never updates.
  - Sequence: value 3, user sets 5, `form.value` set back to 3, user sets 5 again. The editor shows 5, the model holds 3, no `change` fires.
  - This is the "reuse one form across records" pattern that a row-detail editor uses.
  - Fix: have `sync` update the dedupe baseline (for example a WeakMap written by both `put` paths), or compare against the model value.
  - **Clears with:** a unit test that commits, syncs a different value, commits the first value again and expects a second `set`. It must fail with the fix reverted.
  - The verifier had to shim `CSS.escape` because `syncPlugins` throws `ReferenceError: CSS is not defined` under the happy-dom setup. A form-level test needs that shim in `src/test-setup.ts`, or belongs in Playwright.

- [ ] **Press or drag inside a row detail at a column-boundary x resizes the outer column** (`src/data-table.ts:3167`, correctness, verified by code trace; the reviewer's Chromium widths were not re-run).
  - `setCursor` and `resizeColumn` have no `inDetail` guard, unlike click, keydown and change.
  - The band is 5px either side of a boundary for mouse and 20px for touch.
  - `trackDrag` also calls `preventDefault()`, so the press fails to focus an input in the detail.
  - This contradicts the doc line "Clicks and keys inside it are left alone".
  - Fix: return early from both when `this.inDetail(event.target)`.
  - **Clears with:** a Playwright case in `tests/table-row-detail.pw.ts` that drags inside a detail at a boundary x and asserts `columns[].width` and the host cursor are unchanged.

- [ ] **A `<tosi-table>` used as a row detail has its selection highlight rewritten by the outer table** (`src/data-table.ts:3312`, correctness, verified by code trace).
  - `updateSelectionVisuals` runs an unscoped `querySelectorAll('.tr')` over the scroll area.
  - Inner data rows lose `aria-selected`; the inner header row gains it when the owning outer row is selected. The inner `selectedRows` stays correct, so model and DOM disagree.
  - "An invoice that opens to its line items" is the documented use case.
  - Same class, plausible but not reproduced: `querySelectorAll('.col-pinned')` at line 3820 writes outer sticky offsets onto an inner table's pinned cells. Fix it in the same pass.
  - Fix: scope to the table's own rows (`:scope > .tr`, as `syncStampedDetails` already does) and skip anything for which `inDetail` is true. Correct the now-false comment at lines 3309-3311.
  - **Clears with:** a nested-table Playwright case: select an inner row, select the owning outer row, then another outer row, and assert the inner highlight is intact and the inner header is never marked.

- [ ] **A missing required value on an editor- or plugin-rendered field is listed under "Problems in fields not shown here"** (`src/schema-form.ts:1196`, correctness, verified through the real validator and the shipped helpers; not observed in a mounted DOM).
  - `refreshErrors` passes only `_fields` paths as `known`, and `allFields()` excludes plugin and editor nodes. `Missing x` is therefore never re-keyed onto the field.
  - The CHANGELOG line "Fixed: an error on a plugin-rendered field was never shown under that field" is true for type errors and false for missing-required.
  - Fix: pass every indexed path (`this._index.keys()`, or `_fields` plus plugin paths) as `known`.
  - **Clears with:** a test that a required-missing error and a wrong-type error on an editor field both land in that field's `.schema-error`, with the hidden-errors banner empty.
  - Also drive the uncurated format-plugin case, which the verifier did not run. By the same reading the error would appear nowhere near the field there.
