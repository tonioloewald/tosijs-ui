# 1.16.34 pre-release review

**Historical record: every finding is dispositioned below.**

Tier 0 (`release-doctor`) plus `tier: always-on` (correctness + blast radius) at `depth: fast`,
the practice for an additive patch. Diff: `v1.16.33..HEAD` in `src/`, `tests/`, `CHANGELOG.md`
(spin icons, board #3508).

**Verdict: GO, after the fixes below.**

| # | Lens | Severity | Finding | Disposition |
|---|------|----------|---------|-------------|
| 1 | correctness | major | In a flex container taller than the icon, the spinning span stretched while the svg did not, so the svg orbited the rotation's centre (measured: a circle ~13px across in Chromium and WebKit; 1.16.33 held still) | Fixed: both spans `align-self: flex-start`. `tests/icon-spin.pw.ts` "tall flex row" fails with it reverted (checked). |
| 2 | both | minor | The per-icon `<style>` put its CSS into the `textContent` of anything holding a spin icon (`toHaveText`, caption matching) | Fixed: `<tosi-icon-spin>` adopts one shared sheet into its root on connect; nothing inside the icon. Unit test asserts a button's `textContent` is its caption. |
| 3 | blast radius | minor | "Turning it back on is one CSS rule" was false: the icon's own `<style>` won at equal specificity | Fixed: rules in `:where()`. The CHANGELOG notes that a shadow-root icon needs the rule in that root. |
| 4 | blast radius | minor | `svg2DataUrl` on a suffixed spin icon's svg drops the scale/offset, now on an outer span | Accepted: a spin icon is a composite, not an svg, and a data URL cannot spin. Not disclosed. |
| 5 | blast radius | nit | Strict CSP (`style-src` without `'unsafe-inline'`) | Improved by #2: constructable sheets are not inline `<style>`; the fallback (Safari < 16.4) is. |

Not reproduced: the WebKit main-thread freeze itself, which headless WebKit cannot show. The
evidence is virta's: the same change cleared it on the maintainer's iPhone.
