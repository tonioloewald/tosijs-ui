## Fix before the tag (verified majors)

- [ ] **M1. Glass in dark high contrast is unreadable, at about 1.0–1.85:1** (correctness, verified). File: `src/theme-data.ts:226`, plus `src/doc-system/theme-presets.ts`.
  - **What's wrong:** `.darkmode.high-contrast.tosi-style-glass` keeps the *light* backdrop (`#8fabd6 → #d3e0f2`) under `--text-color:#fff`.
  - **Cause, part (a):** `darkHighContrast` is derived `from: 'highContrast'`, which comes from light, so the values tuned for dark never reach it.
  - **Cause, part (b):** the `invert` step with a generator goes through `generator.dark` and `invertedColors()`. That keeps only values that are entirely a colour literal, so a gradient tuned in light passes into the dark modes un-inverted. Any user `themeFile` that tunes a gradient in light leaks the same way.
  - **Fix:** layer `tuned.dark` under `tuned.darkHighContrast`, or derive it from dark. Also make `invertedColors` map the colour stops inside non-literal values, as `mapColors` already does.
  - **Check that clears it:** extend `tests/preset-contrast.pw.ts` to loop over `highContrast: true/false`, so it covers all 4 modes × 3 presets on both routes. The glass/dark/HC case must fail with the fix reverted. Add a unit test that a light-tuned gradient comes out inverted in dark.
- [ ] **M2. A selected Style preset hides theme-editor edits and saved themes** (correctness, verified). File: `src/doc-system/theme-presets.ts:150`, plus `generate-css.ts:65` and `doc-system.ts` `applyStylePreset`.
  - **What's wrong:** preset rules match `<body>` as well as `<html>`, and every generated variable is declared there. The editor's `:root:not(#…)` cannot outrank a declaration on body.
  - **In dark:** `.darkmode.tosi-style-glass:not(#)` (1,2,0) beats `.darkmode:not(#)` (1,1,0).
  - **After Save:** generate-css writes the presets after the saved theme, so the edit is still hidden.
  - **The doc's promise fails:** the presets doc says "what you tune is saved on top of the site's theme", and that does not hold while a preset is active.
  - **Fix:** decide the precedence and enforce it in both places. Options: scope preset rules to `<html>` only and emit the saved and editor theme after them at equal or higher specificity, or preview with preset-qualified selectors.
  - **Check that clears it:** a new e2e test in `tests/theme-editor.pw.ts`. With `style:'glass'` in light and in dark, an accent edit must reach `--brand-color` on body, and corners must reach `--tosi-radius`. Then Save and reload, and the value must persist under the preset.
- [ ] **M3. Bundle growth is unrecorded, and the root barrel now carries the theme editor** (efficiency and blast-radius, both verified, merged here). File: `src/live-theme.ts:192-200`, plus `src/index.ts`.
  - **Measured:**
    - iife: 517.3 → 532.9 kB gzip (+15.5 kB, +3.0%).
    - Root barrel: 106.0 → 118.3 kB gzip (+12.3 kB, +11.6%).
  - **Cause:**
    - The deprecated root re-export of `TosiThemeEditor`/`tosiThemeEditor` pulls in theme-editor, theme-discovery and css-value.
    - The new `export *` of `css-value` registers `<tosi-css-value>` at import.
    - With no `sideEffects` field, a bundler can drop none of it.

    This is the #133 cost pattern. The verifier's correction: v1.17.9 already shipped a smaller editor in the barrel, so the change is the growth, not the presence.
  - **Fix:** 1.18.0 is a minor, so removal is allowed. Either:
    - (a) drop the root re-export and css-value from the barrel, keep them on `tosijs-ui/theme-editor`, and extend `src/index.test.ts`'s barrel-exclusion list; or
    - (b) keep the alias for one release, and record both measured deltas and the removal plan in the CHANGELOG "On upgrade" section, as was done for prismjs.

    Record the decision either way.
  - **Check that clears it:**
    - For (a): `src/index.test.ts` must fail if theme-editor or css-value sources reach the barrel. Re-measure the barrel.
    - For (b): the CHANGELOG line names both numbers.
- [ ] **M4. doc-site-system.md omits `themeFile`, `themePresets` and `DEV_THEME_FILE`** (docs, verified). File: `src/doc-system/doc-site-system.md:~302`.
  - **Fix:** add both options to the Branding & chrome table. Add a subsection covering:
    - where the file lives and that it need not exist yet;
    - the save-to-source session gate, and the rule that it must be a `.json` inside the project and a JSON object;
    - that the build fails on invalid JSON;
    - the `DEV_THEME_FILE` redirect.

    Link it from the theme-presets and theme-editor pages.
  - **Check that clears it:** a unit test that every `SiteConfig` key appears in the Configuration reference. It must fail today on `themeFile` and `themePresets`.
- [ ] **M5. The "No generator" recipe names functions that can't be imported from root** (docs, verified). File: `src/theme-data.ts:99,117`, plus CHANGELOG.md:32.
  - **What's wrong:** `discoverThemeVariables`, `declaredValues` and `docSystemThemeGenerator` are not exported from `tosijs-ui`, and no named subpath exposes them. They are reachable only through the undocumented `./*` wildcard.
  - **Fix:** export them, or state the import path in the theme-data and theme-editor docs and the CHANGELOG, e.g. `tosijs-ui/theme-discovery`, `tosijs-ui/doc-system/doc-system-styles`. Mind M3 before adding anything to the barrel.
  - **Check that clears it:** a test that imports each name from the path the doc shows, run against `dist/`, and gets a function.

**Findings and dispositions:**

1. **CSS injection through theme values and names** (minor).
   - **Verification:** adversarially verified. The skeptic reproduced it with `bun -e` against `css(themeStyleSheet(resolveTheme(data, null)))`.
   - **Disposition:** a card on this repo's board. Recommended to fix alongside M1–M5.
   - **Reason for deferral:** no escalation on the doc site. Whoever can save the theme file already passes the session gate that lets them edit executable doc sources.
   - **Residual risk:** an adopter who applies a theme JSON from an untrusted party with `applyThemeData` gets arbitrary CSS on their page. That allows attribute-selector exfiltration, UI redress and hiding content. Meanwhile the docs suggest only fonts are dangerous.
2. **themeFile gate would accept executable JSON** (minor).
   - **Verification:** unverified; code read only.
   - **Disposition:** a card.
   - **Reason for deferral:** it needs maintainer misconfiguration first. It is hardening, not a reachable hole.
   - **Residual risk:** if `themeFile` is misconfigured to `package.json` or a dot-dir settings file, a tunnel invitee or trustLan peer could rewrite scripts or agent hooks that run on the next command.
3. **No tests for the themeFile admission rules** (minor/nit).
   - **Verification:** the nit is verified by grep across `src/`, `tests/` and `bin/`.
   - **Disposition:** a card.
   - **Residual risk:** a refactor could loosen the `.json`/object/containment checks while every lane stays green.
