## Fix before the tag (verified majors)

Both majors have one root cause: `GEOMETRY_SUFFIXES` in `src/icon-svg.ts:45` is a drifted second copy of the suffix grammar in `src/icons.ts` (`SUFFIX_RE`, line ~857, with its `(?<=[a-zA-Z_])` lookbehind). The cleanest fix covers both, plus the blast-radius minor: move suffix tokenizing and the r/f→transform mapping into one DOM-free module (for example `src/icon-suffixes.ts`) and have both `icons.ts` and `icon-svg.ts` import it.

- [ ] **M1 (correctness, verified): `edit2_90r` rotates the wrong way in iconSvg.**
  - **What happens:** after `defineIcons({ myEdit: 'edit2_90r' })`, `iconSvg('myEdit')` emits `rotate(-90)`, while `icons.myEdit()` draws +90°. With no lookbehind, the leftmost match is `_90r`, and `_` is parsed as a minus sign.
  - **Related divergence:** `edit20f` resolves to edit2 flipped in iconSvg, but the DOM renderer rejects it.
  - **Why it matters:** the output is valid, plausible-looking and wrong, with no error. That is the class of failure this release exists to remove.
  - **Check that clears it:** a unit test asserting that a redirect to `edit2_90r` contains `rotate(90)`, that `edit2__90r` gives `rotate(-90)`, and that `edit20f` is not treated as a flip of `edit2`. It must fail with the fix reverted.

- [ ] **M2 (docs/correctness, verified): `iconSvg('chevronRight90r')` returns `undefined` with no error.**
  - **What happens:** `icons.chevronRight90r()` renders, but `iconSvg` bails at `if (data[key] === undefined) return undefined` (line ~56) before it reaches `resolve()`. The same early return swallows `tosi$hat`, `spin90Loader` and other inline composition.
  - **Why it matters:** the user's request was "iconSvg should fail with an error message at minimum", and the CHANGELOG says this silent case is fixed.
  - **Fix:** take option (a). When the geometry suffix matches on a registered base, route an unregistered name through `resolve()` and transform it. Throw for an inline non-geometry suffix or stack (`chevronRight50o`, `a$b`), with the same message pointing to `icons.<name>()`. Return `undefined` only for a name with no base at all, and update the doc paragraph and TSDoc to say exactly that.
  - **Check that clears it:** tests asserting that `iconSvg('chevronRight90r')` equals `iconSvg('chevronDown')`, that `iconSvg('tosi$hat')` throws, and that `iconSvg('nonsense')` is `undefined`. They must fail with the fix reverted.
