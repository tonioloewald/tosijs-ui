## Blockers (fix before tagging)

### B1. `positionFloat` saves the CSS `position` instead of the FloatPosition, so `refitFloats()` blanks every open float (correctness, blocker, **verified**)

`src/pop-float.ts:322` and `:329`, read back at `:445`

- **Failure.** Inside the leading block of `positionFloat`, `const { position } = getComputedStyle(element)` shadows the `position` parameter. `element.anchorPosition = position ?? null` therefore stores `''` (popFloat positions the float before it is appended) or `'fixed'` (when the float is re-positioned while connected). `refitFloats()` passes that value back as the FloatPosition. It matches no branch, so all of top, left, right, bottom and transform are cleared and nothing is set. The verifier reproduced it: `popFloat({position:'s'})` gives anchorPosition `""`, then after `refitFloats()` top, left and transform are all `""`.
- **Blast radius.** `refitFloats` runs on every visualViewport `resize` and `scroll`: iOS toolbar show/hide, the on-screen keyboard, pinch-zoom or pan, and desktop window resizes. That covers every open, non-draggable float: menus, tooltips, search-field hints, and the new REPL completion list. It also now re-positions, and so breaks, `remainOnResize: 'remain'` floats that used to stay put. This is the iPhone menu path that the release's own CHANGELOG headline promises.
- **Why the tests are green.** The new test in `src/pop-float.test.ts` (around line 182) asserts only the `--max-height` delta, which `roomOnScreen` computes whatever the offsets are. No test checks the coordinates after a refit.
- **Fix.**
  - Use `const { position: cssPosition } = getComputedStyle(element)` and update the `!== 'fixed'` check to match.
  - Extend the refit test. With an unchanged viewport, top/left/transform must be identical after `refitFloats()`. With a changed viewport, they must be recomputed, not blanked.
  - Consider a Playwright check that fires a visualViewport resize with a menu open.
- **Re-review scope.** Correctness and blast-radius over the remediation diff only, plus a real-browser check of an open menu across a window resize. After that, re-run all four lanes on the new HEAD.

### Virta board (this repo; `TODO.md` is only a pointer)

- [ ] **Creator "undefined getter" trap: sweep the class and add a guard** (blast-radius, minor, **verified**), `src/data-table.ts:1956` and `src/code-editor.ts:174`. These two cases were reproduced:
  - `tosiTable({ sort: fn })` sets a `sort` attribute holding the function's source text, and the property is dropped.
  - `codeEditor({ tjsAutocomplete: cfg })` sets a `tjs-autocomplete` attribute, and the config is dropped.

  Apply the same `?? null` treatment as the pinned-rows fix. Add a unit-lane guard: every public accessor of each exported component returns something other than `undefined` on a fresh instance, or has a recorded exemption.
- [ ] **REPL first-use race** (correctness, minor, *unverified*), `src/live-example/component.ts:1421`. `ensureReplScope()` sets `replWanted` before its `refresh()` resolves. If Enter is pressed in that window, the input evaluates without the example's scope and gives a ReferenceError. Keep the in-flight promise (`replScopeReady`), have `consoleEval` await it, and route both call sites through one gate.
- [ ] **`$`/`$$` prefix collides with a lexical `$`** (correctness, nit, *unverified*), `src/live-example/component.ts:1540`. With the injected `var $` prefix, input such as `let $ = 1` or `class $ {}` becomes a SyntaxError. Either skip the prefix when the input declares `$`/`$$`, or inject the helpers through a parameter scope.
- [ ] **`100dvh` has no fallback** (correctness, nit, *unverified*), `src/live-example/styles.ts:48`. Use `bottom: 0` with top/left/right 0 instead of a height. That fills the viewport everywhere, and dvh is not needed.
- [ ] **Build prints no gzip delta against the last tag** (efficiency, minor, *unverified*), `src/doc-system/site/orchestrator.ts:1201`. Print the delta for `dist/iife.js` and the hydrate entry against `git show <lastTag>:dist/...`. This release's +3.6 kB (478.7 to 482.2 kB) is written up correctly, but only because someone measured it by hand. This is a tooling gap that predates the release.
- [ ] **Refit listener is not batched to one run per frame** (efficiency, nit, *unverified*), `src/pop-float.ts:423`. Coalesce runs with a requestAnimationFrame flag, and read before writing if many floats are ever open at once. Negligible with 1 to 3 open floats.
- [ ] **REPL autocomplete runs code as you type** (completeness gap; no lens weighed it). The first dotted path triggers `refresh()`, which re-runs the whole example mid-typing and repeats its side effects (fetches, timers, DOM). `replEvaluate(path)` then runs getters on every keystroke. Decide whether this is acceptable, and document it or gate it.
