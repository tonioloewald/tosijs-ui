## Fix before the tag

There are no verified majors, so nothing is required here. One cheap docs item is recommended before the tag because it describes a behaviour change that ships in a patch:

- [ ] **(verified, minor) A `strict` build now fails on a `[[target]]` that is not a doc page.** Example: `[[playground]]` pointing at a hand-written `demo/static/playground/index.html`. The href is unchanged (`/playground/`) and still works, but the link gets the `-missing` mark, and `misconfigured(strict)` throws (`src/doc-system/site/generate-site.ts:574`, via `wikilinkTargets` in `routing.ts`, which only knows corpus docs). The 1.16.15 patch ruling covers a new strict failure only where the build was already broken, and this link was not broken.
  - **Minimum:** say in the CHANGELOG and in `doc-site-system.md` that a wikilink must name a doc page, and that a static page needs a plain `[label](/path/)` link. Have the warning text name that escape hatch next to `[[slug|label]]`.
  - **Better (follow-up):** exempt targets that exist under the output dir after static assets are copied.
  - **Check:** after building with `strict: true`, a fixture with a static page and a wikilink to it either passes (exemption) or fails with a message that names `[text](/path/)`.
