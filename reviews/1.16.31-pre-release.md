## Blockers

### B1. A revoked device that also holds the view cookie loops through 302s on every workspace (verified)
`src/doc-system/site/dev-server.ts:2347` (page load) and `:2138` (in-place refresh).

Every device that redeemed a `--link --global` link also holds `tosi_preview`, because `grantCookies` sets both. After `--revoke`, each request runs these steps:
1. `passCheck` ends the session tagged with the device.
2. `globalKeyAccess` falls through to the view cookie and returns `'view'`.
3. `issueSession` mints a session, and `if (pass && revoked) auth.sessionDevices.set(session, pass.device)` tags it with the revoked device.
4. The server answers 302, and the next request starts over at step 1.

The browser ends at ERR_TOO_MANY_REDIRECTS. Fetches from pages already open churn sessions and log `🔒 1 session(s) ended` on every request. The skeptic reproduced this with the real dev-auth functions: round 0 issues a grant, and rounds 1–3 each end one session and issue another. The e2e test misses it because `global-keys.pw.ts:268` sends a revoked pass with no view cookie.

- **Fix:** tag a session with a device only when the pass granted it. That means `grant === (keys.editGrants ?? 'edit') && pass && !revoked.has(pass.device)`, at both sites. Better still, have `globalKeyAccess`/`keyAddsAccess` return which credential granted access, so the two callers cannot disagree.
- **Decide and document** what a revoked device should get: view-only access until the view key is rotated, or a clean 401.
- **Clears when:** a Playwright case sends a revoked `tosi_pass` together with a valid `tosi_preview`, and asserts one 302 followed by a 200 read-only page (or a 401, whichever you decide). The case must fail with the fix reverted.
- **Re-review scope:** correctness and blast-radius over the remediation diff only.

## Fix before the tag (verified majors, no re-review needed)

### M1. The upgrade guidance does not say to rotate PREVIEW_EDIT_TOKEN, and two claims about the old cookie are false (security and docs, verified; two lens findings merged)
`src/doc-system/doc-site-system.md:1175–1181`, CHANGELOG 1.16.31 headline, `deploy/Caddyfile:92–95`.

1. **The old cookie value is now the signing key.** Through 1.16.30 the raw edit key was set as the `tosi_edit` cookie, for 30 days, and was accepted as `?t=<edit key>`, so it is also in browser histories and pasted URLs. In 1.16.31 that same value is the HMAC key for `signPass`/`readPass`.
2. **Anyone with a copy can forge an edit pass that cannot be revoked.** `readPass` puts no upper bound on `exp` and does not check the device against the registry. So a copy of the key from a lost device or an old URL can mint passes with fresh device ids and any expiry. Those passes give write access to every workspace, and `--devices`/`--revoke` cannot see them.
3. **The docs claims are wrong.**
   - "That cookie no longer opens anything" is false: Caddy's `@unauthed` gate still accepts `tosi_edit=<edit key>`. That is deliberate, because revoked.txt is fetched that way, but it means the old cookie still opens the root list, the static previews and revoked.txt.
   - "never leaves your machines and the box" is only true from 1.16.31 on.

- **Fix:**
  - In the CHANGELOG headline and in doc-site-system.md, make rotation a required upgrade step for anyone who used `--global` edit links or `?t=` on 1.16.26–1.16.30. The step: edit both preview.env files, re-run `tosijs-caddy-install`, restart the dev servers.
  - Correct both sentences above.
  - Strongly consider also deriving the pass-signing key from the edit key (an HKDF with a label), so a leaked pre-1.16.31 value cannot sign passes even before rotation.
  - Consider bounding `exp` in `readPass` to at most the grant TTL.
- **Clears when:**
  - The docs and CHANGELOG diff states the rotation step and the corrected claims.
  - If key derivation is adopted: a unit test that a pass signed with the raw edit key is rejected by `readPass`, failing with the derivation reverted.
  - If the `exp` bound is adopted: a unit test that a pass with a far-future `exp` is rejected.
