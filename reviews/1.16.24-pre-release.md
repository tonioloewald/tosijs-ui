## Fix before the tag

There are no verified majors, so nothing is mandatory here. **Recommended anyway**, because the fix is a few lines and the user asked for "the issues mentioned" to be dealt with in this patch:

- [ ] **Bound icon-rule chaining** (`src/icon-rules.ts` ~L125–131, `drawable`/`ruleDraws`). This one fix covers two findings:
  - **(verified, minor; security)** Resolution cost is super-linear. Measured times for `icons['un'.repeat(n)+'Lock']()`: n=50 47ms, n=200 247ms, n=400 1120–1442ms, about 4.5–7.7x per doubling. At v1.16.23 such a name stopped at the first `canResolve` miss, so this is a regression from this diff. Any untrusted icon name can reach it (a CMS field, a user-chosen icon, or `tosi-md` with `allowed-elements` including `tosi-icon`), and the result is a frozen tab.
  - **(unverified, minor; correctness)** A custom rule whose prefix matches the empty string (`iconRules.push({ prefix: /^(?:big)?/, … })`) makes `drawable('nosuchicon')` overflow the stack, because the recursion gets back an unchanged `baseName`. `iconRules` is public mutable API. The code comment "Each step strips a prefix, so it ends" holds only for the built-in rules.
  - **Fix:** recurse only when `matched.baseName.length < name.length`, add a depth cap (e.g. 4; real composites need 2) or a length cap, and memoize per name if convenient.
  - **Clearing check:** add a unit test that (a) an empty-matching custom prefix returns false and does not throw, and (b) `'un'.repeat(2000)+'Lock'` resolves or is refused within a small time bound. Both must fail with the fix reverted.
