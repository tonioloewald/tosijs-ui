## Fix before the tag (verified majors; no re-review needed)

### M1. Every built-in tjs example with no function declaration shows a Docs tab reading "No documentation available"

`/Users/tonioloewald/tosijs-ui/src/live-example/code-transform.ts` about line 494 (`loadTjsDocs`), and `/Users/tonioloewald/tosijs-ui/src/live-example/component.ts` lines 2138-2167 (`updateDocs`). Reported by docs (major, confirmed) and correctness (verifier lowered to minor); one defect, kept at major.

- rc.5's `generateDocsMarkdown` returns the placeholder `*No documentation available*`, not an empty string, and `updateDocs` only suppresses the tab on an empty result.
- A source that does not parse replaces the tab content with "Docs could not be generated: ...", which re-fires on each edit.
- This contradicts the comment at `component.ts:2134` and the CHANGELOG's "generated from its signatures". It is cosmetic: examples still run, and the tab shows only once the code panel is open.
- **Fix:** return `''` from `loadTjsDocs` when the types object has no entries, in preference to matching the placeholder string. Consider keeping the last good docs on a parse error.
- **Check that clears it:** a Playwright case in `tests/tjs-lang-rc-features.pw.ts` where a function-less tjs example has no `.example-docs` after the code panel opens and one with a typed function has it. The case must fail with the fix reverted.

### M2. The 1.16.17 entry does not say that tjs-lang 0.14 can stop existing examples compiling, or how to stay on 0.13.13

`/Users/tonioloewald/tosijs-ui/CHANGELOG.md` line 5; pin at `src/live-example/code-transform.ts:354`. Reported by docs (major, confirmed) and blast-radius (verifier lowered to minor); kept at major, at the low end.

- tjs-lang's own notes list breaks with no compatibility switch: a `wasm {}` block that cannot compile stops the transpile, `unsafe var` / `unsafe eval` are refused, and `predicate => expr` is a compile error.
- The entry lists only what turns on. `release-check`'s own warning asks the notes to say what moved.
- The affected set is narrow: sites with no tjs-lang installed whose examples use those constructs. No failing example was reproduced.
- **Fix:** two sentences. One names the upstream breaks and links tjs-lang's "what breaks" notes. The other states that installing `tjs-lang@0.13.13` keeps the old transpiler, because an installed copy is served same-origin and wins over the CDN pin.
- **Check that clears it:** confirm the opt-out claim against a build with 0.13.13 installed (`/tjs/` serves 0.13.13) before writing it, then `release-check` green.
