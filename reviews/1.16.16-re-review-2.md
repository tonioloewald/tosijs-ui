## Fix before the tag

- [ ] **(major, verified, correctness + blast-radius, deduped) A run superseded during its test block overwrites the newer run's results.** `src/live-example/component.ts:3459-3497`.
  - **Cause:** the new guard at 3459 is the only supersession check on the test path. Three awaits follow it (rAF at 3475, `loadTransform('js')` at 3481, `runTests` at 3484-3487) with no re-check. The run then assigns `this.testResults`, removes `-test-running` (3496) and calls `displayTestResults()` (3497) unconditionally.
  - **Reproduced by both verifiers:** run A waits 300ms in its test block, `refresh()` starts run B, and B settles `{passed:1, failed:0}`. A then resumes against its detached preview and leaves the example `-test-failed` with `{passed:0, failed:1}`.
  - **Mirror case (inferred, not run):** A finishing while B is still testing removes `-test-running` early, so the page census can treat the example as settled.
  - **Scope:** this predates the diff and is not a regression. The trigger is narrow: a second refresh mid-test-block, plus a test that fails against a detached preview. Whether the doc-test gate hits this window in practice was not measured. The lenses disagreed on severity (major vs minor, both marked uncertain); it is kept at major because the outcome is a false failure in the release gate's own signal.
  - **Fix:** apply the identity check already used at lines 3436 and 3441 (`this.runAbort === runAbort`) after each await in the test block, returning before any write to `testResults` or the classes. Optionally pass `runAbort.signal` into `runTests` so the old run's waits stop polling.
  - **Check that clears it:** a unit test beside `superseded-run.test.ts` that supersedes run A while it is inside `runTests` and asserts the newer run's results and class stand after A settles. It must fail with the re-check reverted.
  - **Also correct the `[note]` on `b3a696ff1`** in the fix commit. It says the newer run clears the example's state, which holds only when the newer run finishes last.
