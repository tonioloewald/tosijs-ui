## Minors (verified)

**M1: `defineIcons` shadow warning fires on built-in overrides and on ordinary lowercase names.** `src/icons.ts:597`. Lenses: blast-radius and correctness, merged.
- `ruleDraws()` is true for the built-ins `checkCircle`, `checkSquare` and `unlock`. That is because string rule prefixes (`check`, `un`, `search`) match without a camelCase boundary, so `checkbox` is read as check + box.
- `defineIcons({ unlock, checkCircle })` logs two warnings on every page load in the adopter's production console. Common names from lucide-style packs (`unlink`, `checkbox`, `checklist`, `uncheck`, `unarchive`) warn too.
- The CHANGELOG says "Built-in names never warn" and "once per name". The code has no check for built-in names and no dedupe.
- This goes against the project's output-hygiene rule: the warning changes nothing the reader would do.
- **Fix:** skip the warning when `iconData[name]` already existed before the call, and add a unit test that defines `unlock` and expects no warning. Optionally, require a camelCase boundary after a string prefix. That changes rule matching, so rerun `tests/icon-svg-parity.pw.ts` if you do it.

**M2: Router page, first example's route view loads blank.** `src/router.ts:40`. Lens: correctness.
- The router keeps one module-wide state (`compiledRoutes`/`viewRegistry`). When the Named Views example runs `show()` on load, it redefines the routes, and `renderRoute` clears example 0's default view.
- Measured on load: example 0's view text is `''`, example 1's is `'Editing photo 42'`.
- The commit's claim that "the last to run blanked the others" is fixed is only a workaround: the buttons now redefine the routes when clicked.
- `examples-show-something.pw.ts` counts any sized `button`/`input`/`select` as visible content, so it can't see the blank view.
- **Fix:** drop the on-load navigation from Named Views, or give each example its own route state. Then tighten the spec so controls on their own don't count as content, or add an inline test in `router.ts` that checks the first view has text after load.

## Nits (unverified: sanity-check before acting)

**N1 (unverified): spec slugs come from the committed `docs/` at collection time.** `tests/examples-show-something.pw.ts:25`. Lens: correctness.
- `readdirSync('docs')` runs before the webServer rebuilds, so a page that exists in source but hasn't been built and committed gets no test.
- On a cleaned tree, the module throws ENOENT instead of reporting a clear failure.
- **Fix:** read the page list from the served `sitemap.xml` or from `demo/docs.json` inside the test, or document the limitation in the spec header.

**N2 (unverified): the suffix-before-rule order is duplicated** in `resolveIcon` (`src/icons.ts`) and `resolve` (`src/icon-svg.ts:86`). Lens: blast-radius.
- Both copies were updated correctly, and the parity spec guards against them drifting apart.
- Unlike the suffix grammar and the rule table, the order itself has no single owner.
- **Fix:** move the order predicate into `src/icon-rules.ts` so both resolvers call it. Or record the decision to keep the DOM-free split, with the parity spec as its guard.
