## Fix before the tag (verified majors; no re-review needed)

- [ ] **M1 (correctness + docs, merged): `--link` and `--link --share` changed meaning when a global key is set.**
  - **What happens now:** `bin/tunnel.ts:243` calls `globalLinks([share ? 'view' : 'edit'], ttl)` first. `redeemLink` spends any grant on first use, whatever `linkPolicy` says (`dev-auth.ts:386-391`), and sets a 30-day `Domain=.<preview>` cookie holding the raw key.
  - **Consequences:**
    - A share link is spent by whatever fetches it first, which may be a chat app's link-preview bot.
    - Whoever opens it gets view access to every workspace and every static preview for 30 days.
    - Handing a plain `--link` from phone to headset fails on the second device.
  - **What the docs still say:**
    - `doc-site-system.md` around lines 1178 and 1261-1286 still promises "usable on more than one device", that the share link "ignores linkPolicy: single-use", and a 7-day horizon for one workspace.
    - The CHANGELOG only says "print fresh ones".
  - **Default fix:** keep `--link` and `--link --share` on the old per-workspace links, and make grants opt-in (for example `--global`) or offer them only in the start banner.
  - **Alternative:** if the owner wants the new semantics, rewrite those doc sections, the `--help` text and the bin's output labels to say "single-use, the box's key for 30 days, every workspace". Add a `[change]` bullet that names `--share`.
  - **Check that clears it:** a bin-level test (fake loopback server plus fake ssh) asserting which link type `--link` and `--link --share` print with a key configured. It must fail when the fix is reverted. Also grep the doc for "usable on more than one device" and "ignores `linkPolicy`" and confirm each matches the chosen semantics.
- [ ] **S1 (security): GET /__devlink has no CSRF gate, and grant codes are minted with no cap.**
  - **The gap:** `dev-server.ts:2637` checks only for a loopback peer and that the request did not come through the tunnel. `/__build` next to it also applies `csrfOk`.
  - **The attack:** any page open in the developer's browser can mint live grant codes in bulk by sending GETs to `https://localhost:PORT/__devlink?global=view&domain=…`. Every extra live code improves the odds of guessing one at the redeem gate. A hit returns the box-wide key (edit, if minted with `global=edit`) for 30 days.
  - **Fix:** add `|| !csrfOk(request, viaTunnel)` to the gate. curl sends neither Origin nor Sec-Fetch-Site, so the bin keeps working. Cap outstanding grants at a few dozen.
  - **Check that clears it:** a test where a request to `/__devlink?global=view` with `Sec-Fetch-Site: cross-site` gets 404, and a test that minting past the cap is refused. Both must fail when the fix is reverted.
