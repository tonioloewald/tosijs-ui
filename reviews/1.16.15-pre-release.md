## Minors

Correctness and security first.

**M1. restampSite takes the "previous" stamp from the first textual `iife.js?v=` in a page (verified, reproduced).** `src/doc-system/site/restamp.ts:110`
- A page whose prose contains `iife.js?v=1.2.3` makes it return `{previous: '1.2.3', changed: 1}` without throwing.
- It rewrites the prose and the meta description, and leaves the real `<script src>` and `doc-system.css?v=` stamps stale.
- A second run reports `changed: 0` and looks converged.
- Fix: anchor the match to the `src=` and `href=` attributes the generator writes, replace only there, and add a test with such prose.

**M2. restampSite cannot work on a `bundleEntry` site, and its error misdirects (verified, reproduced on this repo's own `docs/`).** `restamp.ts:110-120`
- Reported by both correctness and blast-radius; merged here.
- `bundleEntry` pages load an unstamped `hydrate-<hash>.js` and never contain `iife.js?v=`, so it throws "nothing to re-stamp. Run buildSite first" straight after a successful build.
- The `hydrateName` branches are unreachable on any site `buildSite` produces, and are untested.
- Fix: either find the previous stamp from `doc-system.css?v=`, or throw a message specific to `bundleEntry` and remove the hydrate branches. Say which in `doc-site-system.md`.

**M3. The duplicate-CodeMirror check fails a `strict` build for sites the duplication cannot affect (verified; two findings merged).** `orchestrator.ts:601`, `codemirror-copies.ts:65`
- With no `bundleEntry` the site ships the prebuilt iife with CodeMirror already inlined, yet the build reports "every `<tosi-code>` renders blank" and throws under `strict` (confirmed by code reading).
- The project root is an origin, so an adopter's own unrelated `@codemirror/state` beside a consistent nested set also trips it (reproduced on a synthetic layout, not with a real package manager).
- It runs and reprints on every watch rebuild, unlike the audit.
- Fix: state the condition in the message, make it non-fatal without `bundleEntry`, report a root-only difference separately, and run it on the initial build only.

**M4. The strict-builds doc promises "previous build output is restored" for a restampSite check that rewrites pages first and restores nothing (verified by code reading).** `doc-site-system.md:1436`, `restamp.ts:136-165`
- A deploy script that catches `SiteMisconfiguredError` and trusts the sentence publishes the inert bundle with freshly cache-busted pages.
- Fix: reorder the check before the write loop (see "Fix before the tag"), or reword the bullet to carry its own contract.

**M5. restampSite silently skips the `<tosi-example>` check when the corpus cannot be read, even under `strict` (verified on the docs side; the security-lens duplicate is unverified but reports a scratch reproduction).** `restamp.ts:146-155`
- A bare `catch {}` leaves `docsHaveExamples` false. This is the swallow-and-continue pattern the project's fail-hard rule forbids.
- Reach is narrow: it needs an absolute `outputDir` with a relative or default `docsJson`, a corpus removed between build and restamp, or a differing config.
- Fix: throw, or route through `misconfigured(config.strict, …)`, and add a test for the unreadable corpus.

**M6. The strict live-example rejection test does not exercise the rejection (unverified by the pipeline; I confirmed by reading that both assertions are unawaited, and did not re-run the race).** `restamp.test.ts:97` and `:112`
- `expect(restampSite(...)).rejects.toThrow(...)` is not awaited at either line.
- At line 112 the next statement overwrites `iife.js` with a bundle that registers both elements, so the first call can see the fixed bundle.
- A regression that stopped strict failing on a missing `<tosi-example>` would stay green.

**M7. Three behaviour changes have no test that fails without them (unverified).** `orchestrator.ts:601`, `code-editor-cm.ts:340`, `orchestrator.ts:1058`
- The `buildSite` wiring of the CodeMirror check, including `tosijsUiDir(import.meta.dir)` from the shipped `dist/` location.
- The `<tosi-code>` try/catch that logs the two-copies explanation. It is the only change here that reaches every consumer's bundle.
- The reworded extensionless-import warning.

**M8. The CodeMirror check does not look from tjs-lang's install location (verified as plausible, not reproduced).** `codemirror-copies.ts:52`
- The gap only bites in pnpm-style isolated layouts or when tjs-lang is nested under a third package.
- Fix: add tjs-lang's resolved directory as an origin when installed, or state the limit in the doc.

**M9. restampSite carries a second copy of buildSite's bundle-registration check (verified; the correctness nit is merged here).** `restamp.ts:56-83` and `:146-165` against `orchestrator.ts:1383-1430`
- The shared primitives (`bundleRegistrations`, `liveFenceLanguages`, `misconfigured`) are single implementations; the glue, file sets and wording are duplicated and already differ.
- No input gives different verdicts today. The cost is future drift.
- Fix: have `buildSite` call `servedBundleProblem` with a subject parameter and share one corpus-has-examples helper. If the twin is kept, record that on the board.

**M10. The `emitDeclarationOnly` advice exists only in a warning string (verified; arguably a nit).** `orchestrator.ts:1061`, `doc-site-system.md:360`
- The speculated second failure is not real: nothing later in `buildSite` reads `dist/*.js`.
- What remains is a reference gap in the `libraryTsconfig` row, and no lane builds with a declarations-only tsconfig.
