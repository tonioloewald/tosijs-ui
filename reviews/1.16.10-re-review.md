## Findings

### Minor

1. **Print waits on an untimed manifest fetch and cover image load (confirmed; correctness and blast-radius, deduped).**
   - Where: `src/doc-system/doc-system.ts:375`; `src/doc-system/print-window.ts:85-124` (`resolveBookCover`, `loadImageInPage`).
   - What: the popup opens, then `await resolveBookCover(...)` runs before `document.write` and `printWhenReady`. There is no AbortSignal, timeout or race, and the try/catch only handles rejections.
   - Effect: a stalled request leaves a blank popup and print never fires. The reviewer reproduced this by routing `/epub-volumes.json` to never respond.
   - Scope: this is a regression in this diff, since the action was synchronous before. It reaches every `tosijs-ui/site` adopter with `epub` on; `printCover: false` is the only opt-out.
   - Why it stays minor: the files are same-origin static, closing the popup and retrying recovers, and nothing is lost.
   - Fix: bound the lookup inside `resolveBookCover` (`AbortSignal.timeout` on the fetch plus a timer around `loadImage`, about 2-3s) and resolve `undefined`. Add a unit test with a never-settling `fetchFn` and `loadImage`.

2. **`attachCovers` accepts any `<stem>-cover.<ext>` in the output dir (unverified; correctness minor and blast-radius nit, deduped).**
   - Where: `src/doc-system/site/epub-volumes.ts:70`.
   - What: a volume named `cover` produces `b-cover.epub`, which the predicate accepts as the default volume's cover image. The lens probed this with a sorted listing. Print then silently drops the cover.
   - Same rule, second case: an adopter's static `b-cover.jpg` beside the generated `b-cover.png` is picked by sort order.
   - Sanity-check before acting.
   - Fix: have `buildEpub` report the cover path it wrote. At minimum, restrict to image extensions and warn on multiple matches. Add the `cover` volume case to the test.

3. **`attachCovers` and `printCoverManifestUrl` are not exported from `tosijs-ui/site` (unverified; blast-radius).**
   - Where: `src/doc-system/site/index.ts:58`.
   - What: `generateSite`, `buildEpub` and `listEpubVolumes` are public and `GenerateSiteConfig` documents `bookVolumes`, but the two helpers that build the manifest's cover fields are internal.
   - Effect: an adopter running their own orchestration must predict the cover name, which is the defect this commit removed.
   - Fix: export them (and `VOLUME_MANIFEST`) and name them in `doc-site-system.md`, or record that cover support is `buildSite`-only.

### Nit

4. **`makeCover` labels non-PNG/JPEG/GIF covers `image/png` in the OPF (confirmed; correctness).**
   - Where: `src/doc-system/site/epub.ts:714-726`.
   - What: the test and CHANGELOG now use `art.webp` as the canonical explicit cover. The sidecar is correct, but the ePub manifest declares `cover.webp` as `image/png`.
   - The mislabel is pre-existing and Print is unaffected. Reader or epubcheck rejection was not observed.
   - Fix: add webp and svg to the media-type ladder, and assert the OPF media type in a test.

5. **The missing-cover warning in `makeCover` has no test (unverified; correctness).**
   - Where: `src/doc-system/site/epub.ts:709`.
   - What: the CHANGELOG promises the warning, and deleting the branch leaves every lane green.

6. **The manifest filename and default-volume key are spelled as literals instead of the existing constants (unverified; blast-radius).**
   - Where: `src/doc-system/site/orchestrator.ts:813` and `:1904` use `'epub-volumes.json'` instead of `VOLUME_MANIFEST`; `print-window.ts` uses `v.book === ''` instead of `DEFAULT_BOOK`.
   - Effect: drift would silently lose the Print cover with unit tests green.
