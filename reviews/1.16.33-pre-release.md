- [ ] (unverified, nit) `src/doc-system/site/invite-page.ts:1118`: the "No live link has the code" page shows the typed text upper-cased but not digit-folded (5→S and so on), so it differs from what was looked up. **Docs**
- [ ] (unverified, minor) `dev-server.ts:2566`: the "expired" page says a link works "for a few minutes after it is printed". `--share` links (up to 24h, `--share-ttl`) and `linkTtlMinutes` links also retire as expired. Either use wording that is always true, or carry the TTL on the retired entry. Pin a share link past its TTL as "expired" in dev-auth.test.ts.
- [ ] (unverified, minor) `doc-site-system.md:1312` claims the access log is "readable by root and Caddy only", and nothing enforces it. Also rename or annotate the test "the access logs never record a link credential": short-link codes are logged in paths, by design.
- [ ] (unverified, nit) `invite-page.ts:57`: the JSDoc for `mistypedCode` says it covers spent and expired codes. It is passed only for 'unknown'. Reword it.

**Security hardening**
- [ ] (unverified, minor) `bin/resolve-site-config.ts:238`: `embedGatePage` runs before the installer's sed fills `__PREVIEW_TOKEN__` / `__PREVIEW_EDIT_TOKEN__`. A future gate-page edit that names a placeholder outside an HTML comment would publish the real key on an unauthenticated page. The leftover-placeholder guard would not catch it. Throw on `/__PREVIEW_(EDIT_)?TOKEN__/` in the comment-stripped page, and add a test.
