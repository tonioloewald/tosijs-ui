   - **File:** `CHANGELOG.md:3`.

2. **`tosijs-checklist clear` / `clearChecklist()` runs rm -rf on any folder named by `--dir` or `DEV_CHECKLIST_DIR`** (correctness + blast-radius + security; verified by three lenses; reproduced). This blocks under rule (b): irreversible data loss.
   - **File:** `src/doc-system/site/checklist-store.ts:225`.
   - **What's wrong:** the function is `rmSync(dir, { recursive: true, force: true })` on `checklistDirFor('.', flag('dir') ?? env)`, which is just a `path.resolve`. `--dir=.` deletes the cwd, `.git` included, exits 0 and prints nothing. The reproduction deleted a `shared/` tree that held an unrelated file. The docs invite moving the folder and give no warning. `clearChecklist` is also public in `tosijs-ui/site`.
   - **Fix:** remove only what the store owns: `list.json`, `answers.json`, `schematics/` and any `*.tmp` leftovers. Then `rmdir` the folder only if it is empty. `postChecklist` is already scoped this way.
   - **Clears when:** a unit test clears a dir that holds an unrelated file and asserts the file survives. The test must fail with the fix reverted.

## Follow-ups: this repo's board (virta, project tosijs-ui)

Minors that are verified:
- [ ] **Comment loss from a poll or refresh during the 600 ms debounce** (correctness, verified minor). `src/doc-system/checklist-panel.ts:176`.
  - **What's wrong:** `refresh()` overwrites `editor.answers` while a send is pending. The next 👍 or 👎 then sends `comment: ''`, which wipes the saved comment and blanks the textarea. `state.answers = editor.answers` writes the stale copy back.
  - **Fix:** skip or merge items that have pending or in-flight sends. Or read the comment from the textarea in `handleClick`.
  - **Test:** set answers while a comment is pending, then give a verdict.
- [ ] **Control characters in `page` and `comment` reach `status`/`wait` output raw** (security, verified minor). `checklist-store.ts:312`, `:437`.
  - **What's wrong:** forged `PASS` lines, injected instructions and OSC-52 escapes all pass through.
  - **Fix:** refuse C0 and C1 characters in `page` (parse it with `new URL`), and escape every free-text field in `formatChecklistResults`, as `trustLanWriteRecord` already does.
  - **Test:** a newline and an ESC in `page` and in `comment`.
- [ ] **The default store is a predictable name in shared `/tmp` on Linux** (blast-radius, verified minor). `checklist-store.ts:85`.
  - **Fix:** `mkdirSync` with mode `0o700`, then lstat and check the owner uid, as `session-secret.ts:88` does. Or prefer `XDG_RUNTIME_DIR`.
- [ ] **The exported `checklistHandler` has no same-origin check** (security, verified plausible). `checklist-handler.ts:66`.
  - **What's wrong:** it relies on the JSON content type alone. Behind permissive CORS middleware (Hono `cors()`), any page can POST verdicts.
  - **Fix:** move `isSameOriginRequest` into a DOM-free module and apply it inside the handler.
  - **Test:** `Origin: https://evil.test` plus JSON gets a 403.

Minors and nits that are unverified (sanity-check before acting):
- [ ] **(unverified) Refused readers' 15 s polls flood the refusal log** (correctness + security, merged).
  - **What's wrong:** LAN devices without trustLan and share-link tunnel sessions log about 4 warnings a minute per tab, which buries real refused writes.
  - **Fix:** log quietly for GET `/__checklist`, as `admit()` already does for HEAD, and/or stop polling after a 403.
  - Also merged here: the efficiency nit to back off when no list is posted.
- [ ] **(unverified) The panel's send queue reads `listId` when the send runs**, which bypasses the 409 replaced-list guard. Also, a failed send's `refresh()` can close the panel silently.
  - **Fix:** capture `listId` when the change is made, and keep the panel open on error.
- [ ] **(unverified) `pageSchematic` clips only to the viewport.** Rows scrolled out of an overflow container, children of an `opacity:0` ancestor, and iframes are drawn as visible. `src/page-schematic.ts:100`.
  - **Fix:** carry a clip rect and an ancestor-transparency flag down the walk, or document the limit. Add a case with an `overflow:auto` container.
- [ ] **(unverified) Unknown or misplaced checklist JSON keys are dropped silently** (`step`, `link`, `items` next to `sections`). `checklist-store.ts:144`.
  - **Fix:** refuse unknown keys through the existing `{ problem }` path, and document it.
- [ ] **(unverified) Some new exports appear in no consumer doc:** `pageSchematic`/`SchematicOptions`, the store functions, and `setChecklistEndpoint`/`openChecklist`/`closeChecklist`/`checklistWaiting`.
- [ ] **(unverified) No server-level test that `/__checklist` and `/__checklist/answer` go through `admit`.**
  - **Fix:** list the admitted endpoints in one place, then iterate it: cross-origin gets a 403, and a tunnel request without a write session gets a 403.
- [ ] **(unverified) Dev-only checklist code ships in every production doc-site bundle and the CDN iife** (~4.8 kB gzip).
  - **Fix:** load it lazily on `hasChecklistEndpoint()`, or record it in the CHANGELOG as a deliberate cost.
- [ ] **(unverified, nit) `pageSchematic` walks the whole DOM synchronously on each verdict.** Measure it on the largest doc page, and prune offscreen subtrees if it takes more than a frame.
- [ ] **(unverified, nit) The adopter snippet uses `import.meta.env.DEV`**, a Vite idiom, next to a Bun.serve example (`doc-site-system.md:918`). Make it bundler-neutral.
- [ ] **(unverified, nit) `TosiChecklist.handleClick` calls `this.render()` directly** (`src/checklist.ts:270`). Use `queueRender()`, or a separate per-item update method.
- [ ] **(unverified, nit) The auto-id rule and the URL predicate are each written twice,** in `checklist.ts:122/128` and `checklist-store.ts:170/126`. Move both into `checklist-client.ts`.
- [ ] **(unverified, nit) The shadow-root listener workaround in `<tosi-checklist>` doesn't cite the upstream tosijs task** (`src/checklist.ts:305`). Add the upstream task id to the comment.
- [ ] **#4182 item 3:** an adopter doc example that `test-consumer` runs from a foreign cwd. Close #4182 with this as a new card, or keep #4182 open on it.

**Findings and disposition:**
- **Blocker:** clear rm -rf (major, irreversible). Verified by reading the code and by a scratch-dir reproduction in three lenses. Disposition: fix before the tag. The fix commit is to be recorded.
- **Minor:** control characters in agent output. Verified by running the store functions. Disposition: board card. Residual risk until fixed: only an already-admitted answerer can make the agent misread a verdict or send escapes to the terminal. The exit code stays honest.
- **Minor (plausible):** the adopter handler has no same-origin check. Verified by reading the code. It is not reproducible in this repo's own stack because the handler answers OPTIONS itself. Disposition: board card. Residual risk: an adopter who puts permissive CORS middleware in front of the handler, with a cookie-less `admit`, lets any page forge verdicts.
- **Minor:** predictable `/tmp` store on multi-user Linux. Verified by reading the code. Disposition: board card. Residual risk: on a shared Linux host, a local user can read or plant dev-time checklist data.
- **Minor (unverified):** no server-level admission test for /__checklist. Disposition: board card. Residual risk: a refactor that loosens the wiring would pass every lane.
- **Minor (unverified):** the refusal log flood. Disposition: board card. Residual risk: real refused writes are hard to see in the log.
