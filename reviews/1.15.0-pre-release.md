## Blockers (must clear before `git tag`)

### B1 — Prism grammars are loaded by a bare, runtime-computed specifier; no browser can resolve it, and the failure is silent
`src/doc-system/highlight.ts:216-219` — *reported independently by correctness, blast-radius and efficiency; all three verified.*

```js
await import(/* @vite-ignore */ `prismjs/components/prism-${grammar}.js`)
} catch { return false }   // treated as "no such grammar", not as an error
```

The specifier survives verbatim into `dist/iife.js`, `dist/doc-system/highlight.js` and `docs/hydrate.js`; no import map is emitted; no grammar chunks exist in `docs/_chunks` (16 entries, none a grammar). Measured in headless chromium against the committed `docs/`:

- `import('prismjs/components/prism-rust.js')` → `TypeError: Failed to resolve module specifier`.
- `/highlight-block/` — the new public component's own documented showcase, `<tosi-highlight language="rust">` — renders **0** `.token` spans. Zero console output.
- `/doc-site-system/` hard load: **531** token spans (build-time pass, which runs under Bun and works). Same page after one client-side nav: **23** — the `javascript` block only. typescript 412→0, json 67→0, bash 23→0, yaml 5→0, markdown 1→0.

Prism core ships only `markup/html/xml/css/clike/javascript/js`. Everything the design note cites as the *reason* for choosing Prism — typescript, json, bash, python, rust, yaml, diff — is unreachable in any browser. Three shipped claims are false as a result: `highlight-block.ts` ("grammars load on demand, so a page pays only for the languages it shows"), `doc-browser.ts:1142` ("keeps the pre-rendered page and its hydrated self identical" — 28 of 29 blocks differ), and the CHANGELOG. Under webpack the non-static specifier instead pulls a context module over `prismjs/components` (2.8 MB, 597 files) into a lazy chunk — the opposite failure, and one that undercuts the #120 bundle-weight argument for choosing Prism.

No lane can see it: `src/doc-system/highlight.test.ts:145` asserts `ensureGrammar('rust') === true` and passes, because Bun resolves the specifier. `src/index.test.ts` asserts only that prism is *split out*, never that a grammar loads.

**Fix**: replace with a statically analyzable map of thunks — `const GRAMMARS: Record<string, () => Promise<unknown>> = { typescript: () => import('prismjs/components/prism-typescript.js'), … }` — capped at the languages worth shipping, so every bundler emits real chunks and Bun can inline them in the iife (measure the iife delta; a static map must not flatten ~290 grammars into the entry). Separately, `ensureGrammar` must stop conflating "could not resolve the module" with "no such grammar": warn once, as the missing-core path already does. The silent `false` is why this shipped.

**Re-review scope**: correctness + blast-radius over the remediation diff, plus a browser re-check (client-side-nav token count on `/doc-site-system/`, and `<tosi-highlight language="rust">`) against a rebuilt `docs/`, plus one efficiency check of the emitted chunk set.

### B2 — The site's syntax-highlighting palette is unreadable in the default (light) theme — every token type fails WCAG AA, four are effectively invisible
`src/doc-system/doc-system-styles.ts:534-566` (also missed by every lens pre-verification; caught as a completeness gap)

`--code-bg` is `#fdfdfd` in light mode (`.darkmode` flips it to `#020202`), but the `.token.*` defaults are the VSCode **Dark+** literals with no light variant and nothing under `.darkmode`. Measured with computed styles on the committed site (`docs/doc-site-system/index.html`, light scheme, real `<pre>` background `rgb(253,253,253)`):

| token | colour | contrast |
| --- | --- | --- |
| function / class-name | `#dcdcaa` | **1.39:1** |
| operator | `#d4d4d4` | **1.46:1** |
| property / attr-name | `#9cdcfe` | **1.47:1** |
| number / constant | `#b5cea8` | **1.67:1** |
| tag / selector / builtin | `#569cd6` | 2.00:1 |
| string | `#ce9178` | 2.60:1 |
| keyword | — | 2.90:1 |
| comment / inserted | — | 3.28:1 |
| punctuation (239 on that page) | — | 3.39:1 |

Nothing reaches 4.5:1. In dark mode the same palette is 6.0–14.7:1, so this is a light-mode-only defect with a cheap fix. Light mode is the correct default — the pre-paint script (`generate-site.ts:395-400`) only adds `darkmode` on explicit/system preference. It reaches the no-JS and pre-hydration page, this repo's own `docs/`, and every `tosijs-ui/site` adopter.

The comment at `doc-system-styles.ts:534`, the one at `src/highlight-block.ts:30`, the `book-html.ts:72` rationale ("the site's code sits on a dark code background") and `CHANGELOG.md:155` ("dark mode is a recomputation rather than a second palette") all state these colours derive from the theme. They are fixed literals with no mode handling — the sentence that would have caught this is itself wrong. The book palette *was* contrast-checked against `#f6f8fa`; the site palette was not.

**Fix**: add a light set and move the dark literals under `.darkmode` (or genuinely derive them through the same luminance inversion), add a contrast assertion against both `--code-bg` values mirroring the book's check, and correct the four false comments/notes.

**Re-review scope**: correctness over the remediation diff, plus re-measured computed contrast in **both** modes on a rebuilt page (the table above is the instrument).

### B3 — The default `reviews/` exclusion has no working escape hatch, drops pages silently, and the CHANGELOG claims the opposite
`src/doc-system/site/docs.ts:192` + `:396`, `orchestrator.ts:693` — *reported by correctness (major) and blast-radius (blocker); both verified. Taken at the higher grade because a shipped release note asserts a behaviour that provably does not exist.*

`traverseDirectory` tests the **basename** first, and `findMarkdownFiles` runs it on the top-level entries of `docPaths` too. Verified: `extractDocs({ paths: ['<tmp>/reviews'], ignore: [...DEFAULT_DOC_IGNORES] })` → `[]`, silently. Trailing-slash, relative and `/.` spellings all fail identically; only naming each `.md` file individually escapes (undocumented, and it cannot carry subdirectories). `ignoreDocPaths` only *appends*, so no configuration re-enables the directory.

Three shipping places state the opposite: `site-config.ts:88-91` ("an explicit path always wins over the default exclusion"), `docs.ts:191`, and `CHANGELOG.md:113`. `orchestrator.ts:685` even names the wrong mechanism ("the exclusion is by basename during traversal, so naming a path directly opts back in" — basename matching is exactly why it doesn't). An adopter with `docs/reviews/`, a reviews chapter, or a `src/reviews/` module loses those pages from the site, sitemap, `llms.txt` and ePub on upgrade with **no warning, no count, no receipt** — the "build succeeds and something is quietly wrong" class this whole release is about. The new `#153` tests cover only the skip-when-scanning-a-parent direction.

**Fix**: exempt paths named explicitly in `docPaths` from the basename test (pass an `isExplicitRoot` flag, or apply basename ignores only *below* the roots). Then make it accountable: when a **default** (not consumer-supplied) ignore skips a directory containing scrapable files, print one line naming the directory, the count withheld, and how to publish it. Add a test for `docPaths: ['docs/reviews']`. If the escape is not fixed, `site-config.ts`, `docs.ts`, `orchestrator.ts` and the CHANGELOG must stop claiming it exists.

**Re-review scope**: correctness + blast-radius over the remediation diff, plus the missing test.

## Majors — fix before tagging, or explicitly defer with a CHANGELOG correction

### M1 — "Highlighted in the ePub and in print" does not happen
`src/doc-system/site/epub.ts:906`, `src/doc-system/book-html.ts:179` *(verified; three lenses converged — correctness major, security minor, blast-radius minor, merged)*

`buildEpub` calls `highlightHtml(html)` with no policy, so it defaults to `'auto'` and `isLiveFence` skips every `js`/`ts`/`tjs`/`html`/`css`/`test` fence — but an ePub has no live examples, so the skip buys nothing there. Counted in the committed `docs/tosijs-ui.epub`: js 91/0 highlighted, html 62/0, css 51/0, test 31/0, tjs 2/0 (**237 plain**) against typescript 47/47, bash 8/8, json 3/3, yaml/scss/markdown 1/1. The corpus's most common language is exactly the one left plain. Verified the skip is not load-bearing: `injectExampleLinks` matches on the `language-*` class, never on the code text, so highlighting cannot break the "Run this example live" links.

`config.liveExamples` is in scope at that call site and is ignored, so a site configured `liveExamples: 'opt-in'` — which `site-config.ts` calls *the* setting for a prose/book site, i.e. the audience this feature was built for — gets highlighted code on the web and plain code in the book.

Separately, `buildBookHtml` (the in-app **Print** path, `doc-system.ts:367`) is synchronous and never highlights at all, so the 13 `.token.*` rules just added to `DEFAULT_BOOK_CSS` match nothing on that path. The CHANGELOG heading is "Static code is syntax-highlighted — on the page, in the ePub, and in print."

**Fix**: give `highlightHtml` a policy meaning "nothing here is live" (or make the argument required so a fourth call site cannot default silently) and pass `config.liveExamples ?? 'auto'` from `buildEpub`; make `buildBookHtml` async or run `highlightBlocks` over the assembled document before printing. Add an `epub.test.ts` case asserting a `js` fence emits token markup — the existing epub tests never look at code blocks.

### M2 — `checkExamples` honours neither `liveExamples: 'opt-in'` nor the new `:static` escape, so a block that will never run can still hard-fail a build
`src/doc-system/site/check-examples.ts:165` *(verified)*

`collectCodeTokens` reduces the info string with `dialectOf` (`/^[a-z]+/`), so ` ```js:static ` becomes `js`; `EXECUTABLE.has(lang)` is the only gate; `isLiveFence` is never consulted and `liveExamples` appears nowhere in the file or in `checkExamplesInChild`'s argv/env. `orchestrator.ts:783` throws on any problem. Reproduced: `function foo(…) { … }`, `function foo() { ... }` and `items.map(item => {` each produce `problems=1` under ` ```js:static `, byte-identical to plain ` ```js `. The failure message advises retagging as `typescript` — precisely the mislabelling this release exists to abolish — contradicting `site-config.ts` and `CHANGELOG.md:209`.

Narrowed, and it is why this is not a blocker: it is not a regression (1.14.1 behaved the same), `html`/`css` are absent from `EXECUTABLE` so the CHANGELOG's motivating case is unaffected, and `checkExamples: false` is a real if corpus-wide workaround.

**Fix**: thread `config.liveExamples` through `checkExamplesInChild`, keep the mode suffix in `collectCodeTokens`, and gate on the same `isLiveFence(lang, mode, policy)` the highlighter and `insertExamples` use — which is what `doc-system/example-policy.ts` exists to guarantee.

### M3 — The cache-busting stamp excludes `doc-system.css` despite listing it, and the "release builds keep the version" branch is unreachable
`src/doc-system/site/orchestrator.ts:1441` *(verified)*

`stampInputs` names `${PUBLIC}/doc-system.css`, but PUBLIC is moved aside and recreated empty at L654 and the stylesheet is not written until L1520 — ~80 lines *after* `generateSite` consumed the stamp. The hash loop silently `continue`s on a missing file. Reproduced byte-for-byte: sha256 of `docs/hydrate.js` + `docs/iife.js` = `e98ee193f5b3`, exactly the `?v=` on `doc-system.css` in every built page; including the CSS gives `6a37168501b1`. So a `config.theme`-only change (passed to `generate-css` as argv, never entering a bundle) deploys new CSS under an unchanged URL and returning visitors keep the old stylesheet. Before this change a version bump always moved that URL — a regression for the release case, and notable because the motivating report (#151) was someone editing CSS that was already being served.

Second half: `opts.lock ? releaseStamp : hash`. No shipped caller passes `lock: true` (`bin/dev.ts:91` → `{ skipAudit }`, `dev-server.ts:1433` → `{ skipAudit: true }`, `smoke-consumer.ts:138` → `buildSite(config)`); `grep -rn "lock: true"` finds nothing. `CHANGELOG.md:137`'s "release builds keep the version" never happens, and an adopter passing the perfectly reasonable `lock: true` silently flips stamping mode — `lock` means "acquire the build lock".

**Fix**: generate the stylesheet before computing the stamp (or hash the CSS source/theme JSON), and replace the `opts.lock` test with an explicit `opts.release`/`config.assetStamp` mode — or drop the branch and document that the stamp is always a content hash, which is what ships.

The skipped ones are not equally safe to skip here: **ecosystem** and **dx** bear directly on the new optional peer and the new public API, and both blockers B1/B3 are ecosystem-shaped (they hurt adopters, not this repo).
- **G3 — Optional peer + literal dynamic import, unverified and potentially blocker-class.** `highlight.ts:177`'s literal `await import('prismjs')` is reachable from the root barrel with `prismjs` declared `peerDependenciesMeta.optional`. CLAUDE.md records as *measured* that this exact pattern fails a consumer's build when the package is absent. `bin/smoke-consumer.ts`'s new check verifies every shipped bare import is *declared*; it never builds a consumer with prismjs **absent**. I attempted to reproduce during triage and the probe was **invalid** — the scratch tree inherited a `node_modules` containing prismjs, and Bun auto-installs bare specifiers from its cache besides. **Settle this before tagging**: run `bun run test-consumer` and confirm (a) the scratch install does *not* pull the optional peer, and (b) the consumer build still succeeds. If it fails, this is a fourth blocker.
- **G4 — The iife/CDN path was never checked by anyone.** Folded into B1 (Prism core is inlined, grammar loading is not), but worth stating separately because it is the artifact CLAUDE.md calls the most-loaded, and no lane exercises it in a browser at all.
- **G5 — Escaping is tested only on a benign case**; covered by the security follow-up above, restated here because the design note's "build-time trust" assumption is *not* `<tosi-highlight>`'s contract.
