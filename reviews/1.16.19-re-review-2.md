## Minors

1. **(verified, minor; correctness) `src/icons.ts:933`: iconSvg and the renderer disagree on suffixed names that start with a rule prefix.**
   - **What happens:** `icons.checkCircle90r()` renders the `check` rule over a rotated `circle` (`check75o_00aa00S$circle90r75s50o`). `iconSvg('checkCircle90r')` returns the registered `checkCircle` SVG, rotated. `checkSquare0f` has the same problem.
   - **Cause:** `resolveIcon` runs `composeIcon` before `parseStyleSuffixes`, while `icon-svg`'s `resolve` tries the registered base plus suffixes first.
   - **Scope:** the ordering predates this diff, but this diff states the parity contract. The parity test only samples built-in redirects plus `chevronRight90r`, so it cannot see this. Only a few registered icons are affected (`check*`, `search*`, `cancel*`, `un*`), and no built-in redirect uses such a name.
   - **Fix:** this is cheap enough to fix before the tag if convenient. Otherwise file it.
     - Pick one order for both paths. The recommended order is registered base plus suffix first, since a rotated `checkCircle` is what an author means. Either check in `resolveIcon` whether `splitSuffixes(prop).baseName` is registered before calling `composeIcon`, or make `composeIcon` skip a rule when the suffix-stripped name is registered.
     - Add `checkCircle90r` and a flip such as `checkSquare0f` to the parity pairs, and add a unit assertion.

2. **(unverified, minor; correctness) `src/icons.ts:813`: a third copy of rule matching remains in `parseStyleSuffixes` and has drifted from `matchRule`.**
   - **What happens:** a RegExp prefix is matched with `.test(baseName)`, with no `(.+)$` tail. Neither a string prefix nor a RegExp prefix checks that the base resolves. For example, `unFoo50o` warns about `unFoo` rather than about the name the author wrote.
   - **Impact:** output is the same placeholder today, but this is exactly the drift the commit says it removed.
   - **Fix:** replace the inline `.some()` with `iconRules.some(r => matchRule(r, baseName) != null)`, or with `ruleDraws(baseName)`. Verify the claim first.
