## Findings

### Minor

**F1. The CHANGELOG overclaims that "a replaced built-in runs everywhere" (verified, confirmed). Lens: correctness. Location: `CHANGELOG.md:58`, `src/doc-system/site/check-examples.ts:236`.**
`checkExamples` still transpiles live `tjs` fences with `loadTransform('tjs')`, which is the installed or pinned tjs-lang. It never sees a site's `registerDialect('tjs', …)`.
- A site that overrides `tjs` because its tjs-lang accepts newer syntax fails the build on correct examples. tjs-lang moving AJS into doc pages is the motivating adopter.
- That site also ships a dead bake that the page throws away.
- The only escape is `checkExamples: false`, which turns off checking for js and ts too.

The fix now is to narrow the sentence to runtime and say that the build-time check still uses the installed tjs-lang. The follow-up is a SiteConfig way to declare that `tjs` is overridden, so the tjs check and bake are skipped.

**F2. Nothing tests the highlighter's switch to case-sensitive live-fence checks (unverified). Lens: correctness. Location: `src/doc-system/highlight.ts:476`, `:572`.**
The lens reports reverting both call sites to the lowercased lookup, and all 657 doc-system tests still passed. The B1 regression test covers only insertExamples and save-to-source. If either copy is "tidied" back, the highlighter and insertExamples silently disagree again. This is the same class of bug the release was already bitten by.

**F4. The test-only hook `resetBuiltInDialectsForTests` ships as public API (unverified). Lens: blast-radius. Location: `src/live-example/dialects.ts:132`.**
It is emitted into `dist/live-example/dialects.{js,d.ts}` and can be imported as `tosijs-ui/live-example/dialects`. An adopter that calls it silently clobbers their own `tjs` override. Removing it later would break a patch-level contract.
- Before tagging, at least add a JSDoc note that it is not supported API.
- Better: mark it `@internal` with `stripInternal`, or move it to a test-only module.

### Nit

**F3. The `language-*` class regex is still written out twice in highlight.ts (unverified). Lens: correctness. Location: `src/doc-system/highlight.ts:533`, `:568`.**
This contradicts the new comment saying the pattern exists "only in `languageOfClass`". The fix is to build both regexes from the exported `LANGUAGE_CLASS.source`, or soften the comment.

**F5. The CHANGELOG says "case-sensitive as they were in 1.16.0", but rendered output changes (unverified). Lens: blast-radius. Location: `CHANGELOG.md:58`.**
In 1.16.0, `isLiveFence` lowercased the language, so an uppercase fence like ` ```JS ` rendered plain and unhighlighted on the static site and in the ePub. It is now Prism-highlighted. This is a benign improvement, but it is a visible change in every adopter's pages and books, so the note should say so.

**F6. The creator trap where an `undefined` default stringifies a function into an attribute is recorded only locally (verified, confirmed). Lens: blast-radius, with a practices and ecosystem tail. Location: `CHANGELOG.md:30`, `src/search-field.ts:453-456`.**
The workaround is `textTest = null`, plus a source comment and a CHANGELOG entry. There is nothing in CLAUDE.md, Using-Components.md, the shared practices or UPSTREAM.md. The verifier found no second live instance in this repo, so the cost is that the next author hits the same trap, not a shipped defect.
