## Minor

1. **(verified) `setStripExportsForTests(undefined)` discards the real `stripExports` for the rest of the process, and the "tjs-lang cannot" test is order-dependent.** `src/live-example/code-transform.ts:452`, `src/doc-system/site/check-examples.test.ts:245,250`. Merged from three findings (correctness ×2, blast-radius ×1).
   - `loadTjs()` records the real function once, because `tjsOnce` is memoised. The test's reset to `undefined` erases it with no way back, so later tests in the same `bun test` process see a tjs-lang that "cannot".
   - In the other direction, run alone (`-t "fail it, in both"`), `loadTjs()` re-records the real function after the reset and the test fails with `problems == []`. Correctness reproduced this in a scratch copy with rc.5 (unverified by the skeptic, but consistent with the verified mechanism).
   - Not reachable today: the devDependency is pinned at 0.13.13, which exports no `stripExports`. It arms on the next devDep bump, which the peer range (`^0.13.1 || ^0.14.0-rc.5`) already admits.
   - The seam is also public surface: it is emitted in `dist/live-example/code-transform.d.ts` and reachable through the `./*` wildcard, and `@internal` is only a comment. An adopter calling it with `undefined` disables export stripping until reload.
   - Fix: a tri-state override (`undefined` = use the loaded one, `null` = force "cannot", function = stand-in), with tests restoring to "use the loaded one". Do this before the 0.14.0 pin bump.

2. **(unverified) `tests/tjs-lang-rc-features.pw.ts` skips whenever the feature probe is false, so a green lane can mean "never ran" after the pin moves.** `tests/tjs-lang-rc-features.pw.ts:15-17`. Merged from correctness and blast-radius.
   - `served()` returns false for both features when `__TJS_LOCAL_BASE` is missing or the served bundle lacks the export, and all three tests then skip.
   - Skipping is the intended state today (0.13.13). After the pin moves, a build that stops shipping `/tjs/` would skip instead of fail.
   - This is the only lane that exercises the real upstream contract; every other test uses a stand-in.
   - **Skipped tests, named explicitly:** all three tests in this spec skip on the current pin. They stay scheduled: tie the skip to the installed tjs-lang version and assert the probe is true at >= 0.14.0-rc.5.

3. **(unverified) The console's await detection now reads prelude + body, with no test.** `src/live-example/component.ts:1868`.
   - The change is inert for built-in tjs: correctness probed 14 line shapes on rc.5 and no prelude contains `await`. It only reaches registered dialects.
   - For such a dialect every line takes the async path, so a multi-statement line shows `undefined` and `var`/function declarations do not persist across lines. This is undocumented.
   - Fix: one case in `tests/console-line-js.pw.ts` (prelude containing `await`, plain expression body) and one sentence in the `registerDialect` docs.

4. **(unverified) The ts branch of the build check is a second route to the page's route, and this is the second fix that landed on it separately.** `src/doc-system/site/check-examples.ts:211`.
   - The page shapes ts through tjs-lang `fromTS` then `shapeTjsOutput`; the check uses Bun transpile then `withoutExports`.
   - The twin is deliberate (the build cannot fetch the TypeScript compiler from a CDN). The gap is that the keep-decision is not recorded where the next editor will see it.
   - Fix: a comment at `shapeTjsOutput` naming the check's ts branch as the second consumer of every output-shaping rule.
