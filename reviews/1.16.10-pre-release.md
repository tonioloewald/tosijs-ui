## Confirmed findings (deduped)

### M1. The cover's filename is derived twice and the two copies disagree (minor, confirmed, measured)

Merged from correctness, docs and blast-radius, plus three completeness gaps. Blast-radius asked for a fix or a recorded keep-decision before the tag.

- **Two derivations.** `epubVolumeIdentity` (`/Users/tonioloewald/tosijs-ui/src/doc-system/site/epub-volumes.ts:79`) takes the extension from the configured `epub.cover` string (png/jpg/jpeg/gif, else `.png`) and the stem from the slugged title. `buildEpub` (`/Users/tonioloewald/tosijs-ui/src/doc-system/site/epub.ts:1056`) writes `<output stem>-cover` plus the extension of the cover it actually resolved.
- **Where the prediction is used.** `/Users/tonioloewald/tosijs-ui/src/doc-system/site/orchestrator.ts:1754` bakes it into every page as `bookCover`, and it is `coverUrl` in `/epub-volumes.json`. Both are computed before the ePub build runs.
- **Measured mismatches** (verifier ran `buildEpub` into temp dirs):

| Config | Helper predicts | Build writes |
|---|---|---|
| `cover: 'art.webp'` (exists) | `cover-book-cover.png` | `cover-book-cover.webp` |
| `cover: 'gone.jpg'` (missing) | `cover-book-cover.jpg` | `cover-book-cover.png` (generated fallback) |
| `output: 'custom.epub'` | `cover-book-cover.png` | `custom-cover.png` |

- **Confirmed by reading only:**
  - With no `@resvg/resvg-js` and no explicit cover, nothing is written but the URL is still emitted.
  - With an all-named-volumes corpus, no default volume is built, so `bookCover` dangles. The manifest is not affected in that case.
- **Effect.** Print silently has no cover, because `onerror="this.remove()"` at `/Users/tonioloewald/tosijs-ui/src/doc-system/book-html.ts:219` hides the 404. `coverUrl`, which the CHANGELOG calls "a file you can link", is a dead link.
- **Docs.** `/Users/tonioloewald/tosijs-ui/src/doc-system/doc-site-system.md:926` says an explicit `cover` "keeps its own type", which is false for the webp and missing-file cases.
- **Why the test missed it.** The new case in `epub.test.ts` only uses an existing `.png` with default output.
- **Why it stays minor.** It needs a non-default config, Print falls back to exactly its 1.16.9 behaviour, and nothing regresses. With `epub.output` set, the manifest's ePub `url` was already wrong before this diff.
- **Verifier corrections to the original claim.** The no-resvg case is not warning-free: `makeCover` prints "no cover generated".
- **Related, predates this diff.** The "Download ePub" menu item (`/Users/tonioloewald/tosijs-ui/src/doc-system/doc-system.ts:415`) is a third derivation that ignores `basePath`, `epub.title` and `epub.output`.

### M2. The Print cover page cannot be switched off (minor, confirmed)

- `bookCover` is baked whenever `config.epub` is truthy (`orchestrator.ts:1754`). No `SiteConfig` field, `epub` sub-option or element attribute suppresses it.
- The popup is a separate document and `buildBookHtml` is called without `css`, so there is no CSS escape either.
- The only way back to the old output is `epub: false`, which also drops the ePub.
- The 1.16.2 patch rule in CLAUDE.md counts a new default as additive when it "can be switched off". This one cannot.
- Verifier's qualification: `object-fit: contain` letterboxes the image, it does not distort it. A 600x800 generated raster scaled to a full page will be soft.
- Needs either an opt-out or a recorded maintainer ruling that the 1.16.4 "cosmetic change in a developer-facing component" precedent covers it. The verifier noted the printed PDF is reader-facing output, so that precedent does not obviously apply.

## Unverified leads (sanity-check before acting)

- **(unverified) Cover URL emitted when no cover was written** (correctness, `orchestrator.ts:1754`; docs, `doc-site-system.md:1433`). Three builds emit a URL nothing wrote: an all-named-volumes corpus, no resvg with no explicit cover, and an ePub child that fails or times out. The first two were confirmed by reading during M1's verification; the third was not checked. The doc and CHANGELOG list only two no-cover cases and omit "no default volume".
- **(unverified) Print pagination is only checked in Chromium** (correctness, `book-html.ts:124`). The lens rendered A4 and Letter PDFs in Chromium and got exactly one added page. Safari and Firefox resolve `100vh` in print differently. `tests/print-cover.pw.ts` stubs `window.print` and asserts DOM order and image load, not page count.
- **(unverified) `coverIcon` is named in the 1.16.10 CHANGELOG but absent from the published reference** (docs, `doc-site-system.md:341` and `:1427`). Predates this release.
- **(unverified) `EpubVolume` gains two required fields in a patch** (blast-radius, `epub-volumes.ts:40`). It is the input type of `renderEpubDownloads`, so an adopter building volume literals by hand fails typecheck, although the function reads only `title` and `url`.
- **(unverified) `buildEpub` writes a second file beside `output` and overwrites without notice** (blast-radius, `epub.ts:1057`). The log line names only the ePub. With `output` outside the project, a sibling `-cover.*` file is created there. The test footprint was checked and is contained.

## Completeness gaps (not examined by any lens)

- **CSP.** The cover's only guard against a broken first page is an inline `onerror`. The popup is `about:blank` and inherits the opener's CSP, so under an adopter CSP without `'unsafe-inline'` it will not run, leaving a broken-image page followed by a page break. Needs a named owner (security or blast-radius).
- **Screen preview.** The `.book-cover { height: 100vh }` rule also applies in the popup preview (`autoPrint: false`), where it pushes the title below the fold. Not looked at.
- **Rebuild stability of `docs/tosijs-ui-cover.png`.** It is a new committed 20.9KB binary rasterised by resvg. Nobody checked it is byte-stable across rebuilds, and the site config already notes `docs/tosijs-ui.epub` is "dirty in every diff". It is a candidate for the same churn and for tripping the publish workflow's reproducibility check.
- **Watch rebuild and stale files.** The baked cover URL is briefly dead during a dev rebuild, because the ePub is built in a child process after page generation. An old `*-cover.*` file can linger on a host that does not prune when the cover type changes or `epub` is disabled.
- **Other entry paths.** Not exercised:
  - `<tosi-doc-system>` embedded with a hand-written `config`; `bookCover` is undocumented as a config key for embedders.
  - The legacy `createDocBrowser` SPA.
  - A `basePath` site end to end.
  - The tunnel or off-localhost origin.
- **Title mismatch.** Nobody checked that the default volume's cover title matches the title Print uses (`projectName` or `document.title` versus `epub.title`).
- **Spec brittleness.** `tests/print-cover.pw.ts` runs only in chromium in CI and picks the settings button by geometry (`top < 60`, last header button). That is fragile against header changes and in Firefox and WebKit.
- **`bin/build-book.ts`.** It passes `config.epub` straight through, so it hits the `epub.output` mismatch in M1. Not separately tested.
- **Review surface.** The range is two commits, the feature plus an AAR-only commit. 108 of 118 changed files are generated, so the real surface is about 10 source files under `src/doc-system/`.
