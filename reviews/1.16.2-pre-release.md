## Findings by severity

### Minor
1. **(verified, blast-radius)** The example console is on by default and ships in a patch. A `tosijs-ui/site` adopter with no `bundleEntry` cannot turn it off from the site config.
   - The only page-wide switch is `setExampleConsole(false)`, which is a module-scoped setter (`src/live-example/example-console.ts:91`). The per-fence `{"console": false}` has to be added to every fence.
   - `SiteConfig` already has `liveExamples` but has no console setting.
   - The CHANGELOG announces the visible change. The verified point is not that the change is unannounced, but that a config-only adopter has no switch.
   - Fix: add a declarative `exampleConsole?: boolean` next to `liveExamples` in site-config.ts and bake it into the page so it applies before hydration. Otherwise, record the explicit decision that a default-on panel counts as additive for the patch rule. Either way, name the opt-out route in the CHANGELOG.
2. **(unverified, correctness)** The console marks any object it has already seen as `[Circular]`, so a value that appears twice in one log prints as `[Circular]` even when nothing is circular (`example-console.ts:45`). The `seen` WeakSet never removes an entry. Map and Set print as `{}`.
   - Fix: check only the ancestors on the current path, and give Map and Set a readable form.
3. **(unverified, correctness)** In iframe/ide mode, Errors and Elements print as `{}` (`example-console.ts:36`). The `instanceof Error` and `instanceof Element` checks use the parent window's classes, and the example's values come from the iframe.
   - Fix: check by shape instead (`Object.prototype.toString`, `nodeType`/`tagName`).
   - Test: pass a `node:vm` Error to `formatConsoleValue`.
4. **(unverified, efficiency)** Every log line is formatted before anything checks whether it will be kept (`example-console.ts:75`, `component.ts` `appendConsoleLine`). Lines from aborted runs and lines past the 500-line cap are still pretty-printed. On top of that, `scrollTop = scrollHeight` runs after every append, which forces a layout per line.
   - Fix: format only after the abort, hydration and cap checks.
   - Fix: past the cap, only update the counter.
   - Fix: scroll once per burst (in a requestAnimationFrame or microtask).
5. **(unverified, efficiency)** The carousel's 100ms `autoAdvance` tick calls `matchMedia()` on every tick, for every carousel, even when `auto=0` (`carousel.ts:117`).
   - Fix: return early when `auto <= 0`.
   - Fix: create one MediaQueryList at module level, lazily, and reuse it.

### Nit
6. **(unverified, correctness)** The carousel's keyboard-focus pause (`handleFocusIn`/`handleFocusOut`, `carousel.ts:136`) has no test that fails without it. That includes the `:focus-visible` gate, which stops a tap on a phone from pausing the carousel for good.
   - Fix: a Playwright case that tabs in, checks the carousel stays paused, tabs out, and checks it advances again.
   - Fix: a second case where a tap keeps it advancing.
7. **(unverified, security)** No regression test that logged markup renders as inert text in the console panel.
   - Fix: add an assertion to `example-console-panel.test.ts` that logs `<img src=x onerror=…>` and checks the line's textContent equals the string, there is no `img`, and the flag is not set.
8. **(unverified, efficiency)** `running-indicator.test.ts` takes 2.26s of the unit lane's 15.9s because it waits on real timers.
   - Fix: make `RUNNING_DELAY_MS` injectable, or use fake timers.
9. **(unverified, blast-radius)** `prefersReducedMotion()` is copied into `carousel.ts` and `live-example/component.ts:629`.
   - Fix: move it to a shared `src/reduced-motion.ts`. This pairs with the fix in item 5.

## Completeness gaps (from the coverage pass; carry these forward, do not drop them)
1. **Examples that declare `console` now throw.** `execution.ts` injects `console` as an AsyncFunction parameter (lines 164/193, 270/351). Top-level `const console = …` in an example now fails with `SyntaxError: Cannot declare a const variable twice`, and before this change it ran. There is no test and no documentation of it. Nothing in this repo does this, but third-party doc sites might. Document it, or detect it and fall back.
2. The spinner was checked only in happy-dom, so no lane shows it actually appears and spins. This is the user's explicit ask and it has not been checked by eye.
3. In `refresh()`, the runner branch reads `this.parts.running` without a `hydrated` guard. It is probably unreachable, but nobody has confirmed that.
4. The 250ms show/hide race and abort-then-rerun ordering were never run. A flicker is possible.
5. No ruling on version policy (patch vs minor) for the carousel behaviour changes and the default-on console. See the practices follow-up.
6. `DialectRunContext` gained a **required** `console: Console`. That breaks adopter code that builds the context by hand, for example in tests of their own `run` dialect. Consider making it optional in the type. The emitted `.d.ts` files were not compared as API.
7. **No evidence that `bun run test-consumer` ran for 1.16.2.** That lane covers the new `setExampleConsole` export and `dist/live-example/example-console.js` in the packed tarball, and it is required before the release. The doc-test lanes and `bun test` (1617/1617) are green.
8. The gzip delta for `dist/iife.js` was not recorded (168 lines changed). Capture it from `bun run build` and put it in the CHANGELOG or AAR.
9. Docs drift was not checked: `doc-site-system.md`, `Using-Components.md` and `llms.txt` may need the console and spinner behaviour, and the dialect `run` console contract.
10. The prepare commit is not pushed and not tagged. Push, then tag, then run `publish.yml`.
