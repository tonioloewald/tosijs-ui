## Must fix before tag (verified majors, both correctness)

### M1. `allowedElements` is not reactive, so the documented migration path for #179 does nothing (`src/markdown-viewer.ts:165`)
- **What happens:** `allowedElements` is a plain class field. It is not declared in `withAttributes` and has no setter. Setting `el.allowedElements = ['tosi-icon']` after connection does not re-render the element; this was reproduced in happy-dom.
- **Who it breaks:** the component docs (line ~50) and CHANGELOG line 22 both give exactly that assignment as the migration path. It is also the only option for an HTML-declared `<tosi-md>` (the CDN/iife and README flow), because there is no attribute form. Adopters' custom elements disappear with no error.
- **Fix:**
  - Add a `queueRender()` setter.
  - Preferably also add an attribute form, e.g. `allowed-elements="tosi-icon tosi-tag"`, so HTML authors can migrate.
  - Add a test that assigns the property after the first render and awaits `updates()`, without calling `render()` by hand. The existing tests call `render()` manually, which is why they missed this.

### M2. The 1.16.0 CHANGELOG has no entry for the `tosijs-release-notes --check` scoping change (B2), so the release gate is red (`CHANGELOG.md:3`)
- **Gate result:** `bun bin/release-notes.ts --check --version=1.16.0` exits 1 and reports the a45db9e3 `[fix]` bullet as missing.
- **Why it needs a real entry, not a `[note]`:** the shipped adopter bin's behaviour changed.
  - `--check` now reads only the `## <version>` / `## v<version>` section.
  - A missing section is now reported as an error.
  - There is a new `changelogSection` export.
  - Keep a Changelog headings (`## [x.y.z]`, `## [Unreleased]`) no longer match, so a changelog that used to pass now fails. This is verified by the blast-radius lens.
- **Fix:** write the entry and state the expected heading format. Then bump the version, rebuild, and re-run `release-check` as the last step before `git tag`.

Severity note: the verifier lowered M2 from blocker to major, because the fail-closed gate catches it. It remains must-fix because the gate cannot go green without it.
