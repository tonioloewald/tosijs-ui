## Fix before the tag (verified majors, plus cheap confirmed items)

- [ ] **M1. Enter does not open a non-editable `<tosi-select>`** (`src/select.ts:541`, correctness, verified in Chromium, Firefox and WebKit; v1.16.41 opened on Enter).
  - Cause: the button now carries `onKeydown: this.handleKey`, and handleKey calls `preventDefault()` on Enter. That cancels the button's activation, so `popOptions` never runs. Space still works.
  - Fix: only swallow Enter when `event.target === this.parts.value`, or call `popOptions()` when Enter arrives on the button.
  - **Check that clears it:** a Playwright test that focuses the button, presses Enter and then Space, and asserts `aria-expanded="true"` each time. It must fail with the fix reverted.
- [ ] **M2. altText output escapes the alt attribute** (`src/doc-system/site/alt-text.ts:40` → `src/doc-system/render.ts` image renderer; security, verified with the real code).
  - A hook returning `"><img src=x onerror=alert(1)>` renders a live `<img onerror>`.
  - The ordinary caption `A sign reading "Open" & <b>` also breaks the attribute.
  - The renderer behaviour already existed at v1.16.41 for alt text in authored markdown. altText is the first path that sends untrusted, machine-generated text into it.
  - Fix: escape the alt in the image renderer with the existing `escapeAttr`. As defence in depth, have `altMarkdown` escape or reject `"<>&`.
  - **Check that clears it:** tests in `alt-text.test.ts` and `render.test.ts` that feed `"><img onerror>` and `A "quoted" <b>` through applyAltText → renderDocMarkdown, and assert that the alt attribute closes exactly once. Also run the whole `render.test.ts`, because pages whose authored alt contains `"`, `&` or `<` will change.
- [ ] **(Recommended alongside M2) mXSS in `sanitizeExampleHtml`** (`src/live-example/example-hooks.ts:81`). This is rated minor, but the verifier demonstrated a live `onerror` in all three engines with the nested form/mglyph/style payload, and WebKit fired the alert. The sanitize hook is the security boundary for no-code mode and Chat.
  - Fix: insert the fragment the hook returned with `preview.replaceChildren(fragment)`. For the iframe, use importNode into the frame's document instead of a string round trip.
  - **Check that clears it:** a Playwright test with that payload that asserts no `img[onerror]` reaches the preview.
- [ ] **(Confirmed in triage) Palette footer reads "near" in 5 locales.** In `demo/src/localized-strings.ts:12`, `Close` is translated as Lähellä (fi), Nära (sv), 近い (ja), Cerca (es) and Vicino (it). `Navigate`, `Search` and `Clear` have no rows at all, so the #247 footer mixes English with translations on our own site. It is a one-line data fix plus three rows, and you can check it by eye in one locale.
