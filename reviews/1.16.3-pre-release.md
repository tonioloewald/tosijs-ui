## Blockers (fix before tagging)

### B1. Scrolling an anchor's scroller closes a parent menu but leaves its submenu (correctness, major, verified)
`src/float.ts:195` (`scrollMovesAnchor`), `src/pop-float.ts:290`, `src/menu.ts:1583-1585, 1615`

- **The failure.** `scrollMovesAnchor` walks up from a float's anchor. A submenu's anchor is an item inside the parent `<tosi-float>`, which is mounted on `body`. The walk therefore never meets the sidebar or table scroller that holds the root menu button. When that scroller scrolls:
  - the parent float is removed;
  - the submenu returns `false` and stays on screen, still actionable.
- **Orphaning.** The natural next step is to click the menu button again. `popMenu` sees that `poppedMenus[0].menu` is detached and runs `poppedMenus.splice(0)`. That drops the submenu's entry without removing it, so menu dismissal (outside-mousedown, Escape) can no longer reach it.
- **Regression.** In 1.16.2, any scroll closed both menus.
- **Severity.** Major, against the desktop-quality UX bar.
- **Fix.** In `scrollMovesAnchor`, when the walk reaches a `TosiFloat`, continue from *that float's* `anchor`. Alternatively, when the handler removes a menu float, also remove the floats chained to it.
- **Test.** Add a `pop-float` or menu test with a float anchored inside another float, where an ancestor scroller of the root anchor scrolls. Assert that both floats are gone.

### B2. publish.yml stages a tarball it never checked against Pack's hash (security, major, verified)
`.github/workflows/publish.yml:290-333` (stage derive), `:423` (verify), `:213-216` (comment)

- **What runs after Pack.** Pack (L186) records `steps.pack.outputs.integrity`. Three steps then run code that is not locked or pinned:
  - the consumer smoke test, using practices at HEAD;
  - an unlocked extra install;
  - release-doctor, using practices at HEAD.
- **Where the check is missing.** Only after those steps does upload-artifact send whatever `.tgz` is on disk. The stage job hashes the bytes it received, but **never compares** that hash with `needs.build.outputs.integrity`.
- **Why verify can't catch it.** Verify prefers `needs.stage.outputs.integrity`. So it compares the published bytes with the staged bytes, and reports "published bytes identical to the staged tarball" even when a post-Pack step rewrote the tarball.
- **Regression.** In 1.16.2, verify compared against the Pack hash, so the same swap failed verification.
- **The comment is now wrong.** L213-215 says the tarball "is sealed … so an unlocked install's dependencies cannot touch what ships", but nothing reads the recorded hash. This is a gate reporting a pass it did not earn, which this project's fail-hard rule specifically forbids.
- **Fix.** In the stage job's derive step, fail before `npm stage publish` unless `INTEGRITY == needs.build.outputs.integrity`. Later steps cannot rewrite the Pack step's outputs, so this comparison catches a post-Pack swap. Optionally also move upload-artifact to directly after Pack. Correct the L213-216 comment.
- **Fix the template too.** This file is a copy of the `tosijs-coding-practices` template (commit 61721c9), so the same fix must land there. Otherwise the next re-copy brings the gap back. See "Shared practices" below.

### This repo: fix now or file on the virta board (`TODO.md` is now a pointer to the board)

**Correctness and security**
- [ ] **F1 (minor, unverified)**: `positionFloat` (the public API) never updates `float.anchor`; only `popFloat` sets it (`src/pop-float.ts:290`). When an existing float is moved to a new target, scrolls that move the new target are ignored, and scrolls of the old target's container still dismiss it. Fix: set `element.anchor = target` inside `positionFloat`'s `instanceof TosiFloat` block, and drop the assignment in `popFloat`.
- [ ] **F2 (minor, unverified)**: search-field leaves stale ARIA after a scroll closes its hints (`src/search-field.ts:733`). The float now removes itself, and nothing calls `closeHints()`. The input keeps `aria-expanded="true"` and an `aria-activedescendant` pointing at a detached option. Fix: reset the state when the float disconnects, or derive `aria-expanded` from `hintsOpen`. Extend the scroll test to assert `aria-expanded === 'false'`.
- [ ] **F3 (minor, unverified)**: `SiteConfig.dialects` never reaches the ePub child process (`src/doc-system/site/orchestrator.ts:1667`).
  - `buildEpubInChild`'s payload does not carry `dialects`, and epub-cli never calls `registerLiveLanguage`.
  - So on a page where an `ajs` example comes before a `js` example, the ePub's "Run this example live" link points at the wrong example, and every later link on the page shifts the same way.
  - Fix: pass `dialects` in the payload and register them in epub-cli. Add an ordinal-parity test.
- [ ] **F4 (minor, verified, downgraded from major; merges the correctness nit and the blast-radius minor)**: the built-in dialect set `{js,tjs,ts}` is copied in four places: `dialects.ts` `BUILT_IN`, `orchestrator.ts:19` `BUILT_IN_DIALECTS`, `insert-examples.ts:106` `BUILT_IN_NAMES`, and the `SOURCE_LANGS` seed. The orchestrator and insert-examples copies, both new in this diff, compare case-sensitively; the others lowercase.
  - With `dialects: ['TJS']`, the build would still check and pre-transpile tjs with the installed tjs-lang.
  - Fix: export one DOM-free `BUILT_IN_DIALECTS` from `src/doc-system/example-policy.ts` and import it everywhere. Lowercase `SiteConfig.dialects` once when the config is read.
  - If the orchestrator copy must stay, record why and add an equality test.
- [ ] **F5 (minor, unverified)**: `buildSite` writes declared dialects into the process-global live-language registry and never clears it (`orchestrator.ts:1668`). One site's dialects carry over to later builds in the same process (a monorepo build, or a devServer whose config was edited). Fix: pass dialects per build, or snapshot and restore the registry. At minimum, document it in `doc-site-system.md`.
- [ ] **F6 (minor, unverified)**: the credentialed stage job runs `npm install -g npm@^11.15.0`, a floating range, while holding `id-token: write` (`publish.yml:279`). The comment says it uses npm "from the runner image". Fix: pin an exact version and correct the comment. This also needs to go to the template.
- [ ] **F7 (nit, unverified)**: two comments in `publish.yml` describe the old one-job trust model. The L216 comment says the extra install "still runs in the job holding id-token: write". Separately, verify reads NAME, VERSION and LATEST_BEFORE from build-job outputs, which the workflow itself treats as untrusted. Fix: emit those values from the stage job and prefer them in verify. Mirror the change in the template.

**Other nits**
- [ ] **F8 (nit, unverified)**: replacing the built-in `js` dialect with one that has a `docs` hook never shows a Docs tab, because `ensureProductTabs` returns early for `dialect === 'js'` (`src/live-example/component.ts:1108`). 7. **Behaviour change in `<tosi-float>` scroll dismissal, with no adopter check.**

8. **ESM size impact.** `live-example/component.ts` now statically imports `markdown-viewer` (marked + tosijs-kilpi), so `tosijs-ui/live-example` ESM consumers pay for it even without a `docs` hook. The CHANGELOG quotes only the iife delta. Measure the subpath delta, or make the import lazy.
9. **`loadTjsDocs` fallback.** It may bypass the same-origin `/tjs/` copy and fetch from a CDN, and the memoised `null` may block a later successful load. Unverified.
10. **Dev-server lifetime.** `registerLiveLanguage()` runs on every rebuild. Confirm the registry is a Set, so it stays bounded (see F5).

The 8 new lines in `doc-site-system.md` have not been checked against the actual `dialects` behaviour.
