## Strongly recommended before tagging (cheap, same code)

- **C1 (correctness, verified).** The REPL hook is prepended, so it cancels an example's `'use strict'` while the console is on. That is the default. `src/live-example/execution.ts:140` (`withReplHook`).
  - Reproduced: the body `'use strict'\nundeclaredG = 1` throws without the hook. With the hook it silently creates a global.
  - It also affects transpiled tjs/ts output whenever that output begins with a directive, which is gap 5.
  - Fix: insert the hook after any directive prologue, on the same line so line numbers don't shift. Add a unit test where a `'use strict'` example assigns an undeclared name and still throws `ReferenceError` with the console enabled.
- **E1 (efficiency, verified, raised from nit to minor).** The direct `eval` closure is added to every non-runner example run for every reader, whether or not the Console tab is ever opened. `src/live-example/execution.ts:140`, gated in `src/live-example/component.ts:2358` on `consoleEnabled && !runner`.
  - Measured on a heavy top-level scope with a hot closure: Bun/JSC about 105ms → 280ms (2.6x), Node/V8 about 320ms → 475ms (1.5x).
  - It also keeps the whole example scope alive through `replEvaluate` until the next run.
  - Fix: inject the hook only once the code panel or Console has been opened, and re-run then (`showCode` already re-executes). Record the measurement in the `withReplHook` comment.
- **CHANGELOG accuracy.** "No API was removed" is false.
  - The patch removes `console` from the exported `ExampleParts` (`dist/live-example/types.d.ts`), along with the `[part=console]` element and the `-has-console` host class. It also reshapes `liveExampleStyleSpec`.
  - I grepped src, demo/src and tests and found nothing internal that still references them. Removing a styling or parts hook from a developer-facing component fits the recorded 1.16.4 patch ruling, but the sentence must say what was removed.
  - Reword it, and add a `[change]` line.

## Completeness gaps (each one is a follow-up, nothing dropped)

1. **Diff basis is sound.** The tree is clean and `v1.16.3...HEAD` is exactly the 5 shipping commits. dist/ and docs/ were regenerated in the same range. No action needed.
2. **The pop-out editor window was not reviewed.** `buildConsoleView()` is gated only on `consoleEnabled`, so the remote window from `openEditorWindow` also gets a Console tab. That window never runs the example, so the tab shows no logs, `replEvaluate` is never set, and the REPL evaluates against the pop-out's own document. File: hide the Console in remote windows, or carry console and REPL traffic over RemoteSync. (`src/live-example/component.ts` ~1749, 2222-2250)
3. **Patch-vs-minor surface.** Addressed above: the removed hooks have no internal users, and the CHANGELOG wording must be corrected before tagging.
4. **Ecosystem impact on #184.** Addressed under upstream.
5. **The hook on transpiled tjs/ts output is untested.** If tjs-lang or from-ts output begins with `'use strict'`, C1 applies to it too. Add a tjs and a ts example test when fixing C1.
6. **Retention cost.** The always-on hook keeps every example's top-level scope, preview DOM included, alive until that example's next run. The E1 lazy-injection fix also removes this.
7. **`withReplHook` / `ExecutionOptions.onRepl` are new public exports** of `tosijs-ui/live-example` that run arbitrary eval in example scope. Decide whether they should be public or internal, and do it now, while removing them is still cheap.
8. **Lane evidence is unverified on HEAD (5de9931ab).** Run all four lanes before tagging, as the release gate requires: `bun test`, `bun run test-browser`, `bun playwright test` and `bun run test-consumer`.
   - The new specs `tests/nav-search.pw.ts` and `tests/test-only-example.pw.ts` run only on chromium in CI, and the nav-search fix is specifically about Firefox and Safari. Run them with `--project=firefox` and `--project=webkit` locally.
   - Re-measure the CHANGELOG's iife figure (477.0 → 478.5 kB gzip).
9. **The test-only-example fix (dbf17ae09)** now always runs test-only examples' tests for readers on deployed sites. No one audited the existing test-only fences in `src/docs` and the component docs for network or timer side effects. File an audit.
