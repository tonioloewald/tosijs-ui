## Blocker (1)

### B1. `strict` gates the `<tosi-example>` check on a drifted copy of the live-fence predicate (verified, 3 lenses)

- **Where:** `src/doc-system/site/orchestrator.ts:1339-1340`, consumed at about 1365-1371.
- **What:** `docsHaveExamples` is computed with `/^[ \t]*```(js|ts|tjs|test)[ \t]*$/m` and ignores `config.liveExamples`. The tjs-lang check about 120 lines below, in the same function, uses the new `liveFenceLanguages(corpus, config.liveExamples)`. Until 1.16.7 the regex only chose a warning; this release makes it the input to `misconfigured(config.strict, ...)`, which throws.
- **Measured disagreement** (verifier ran both predicates):

| Fence | Policy | Old regex | Actually live |
|---|---|---|---|
| `js` | opt-in | true | no |
| `js` | none | true | no |
| `js:inline` | opt-in | false | yes |
| `js:iframe` | auto | false | yes |
| `js#my-id` | auto | false | yes |
| `html` / `css` | auto | false | yes |

- **False pass:** a corpus whose live fences all carry `:inline`, `:iframe` or `#id` (the only way to be live under opt-in), or are html/css-only, with a `bundleEntry` that omits `tosijs-ui/live-example`, builds green under `strict` while every example is inert. That is the case `strict` was added to stop.
- **False fail:** a prose or book site with `liveExamples: 'opt-in'` or `'none'`, bare `js` display fences and `strict: true` throws "This corpus has executable fences" when it has none.
- **Why it gates the release, though rated major with uncertain severity:**
  - It is a confirmed correctness defect in the feature this release introduces, and a fail-closed gate that fails open is worse than no gate.
  - CLAUDE.md names this exact hazard: `isLiveFence` is THE predicate, and a second copy already caused a shipped defect in 1.15.
  - The fix is one call, so blocking costs little. Shipping it means a second release to correct a contract adopters will have opted into.
- **Caveats the verifiers recorded:**
  - The triggers are narrow. False pass needs no bare `js`/`ts`/`tjs`/`test` fence anywhere in the corpus; false fail needs strict, opt-in or none, and a custom `bundleEntry` without live-example.
  - No end-to-end `buildSite` run was done for either direction.
  - The registered-dialect sub-case was not tested.
  - A reasonable reader could rate this minor. If the maintainer does, the verdict becomes GO_WITH_FOLLOWUPS with B1 as the first follow-up.
- **Fix:** replace the regex with `liveFenceLanguages(corpus, config.liveExamples).size > 0` (or the subset that needs `<tosi-example>`), reading the corpus once and sharing it with the tjs-lang check. Add one test per direction: `js:iframe` / `js#id` under auto counts; bare `js` under opt-in does not.
- **Re-review scope:** correctness and blast-radius over the remediation diff only.

## Recommended in the same remediation (verified, minor)

### M1. `liveFenceLanguages` recognises only three-backtick fences, so the `strict` tjs-lang gate fails open (verified, security)

- **Where:** `src/doc-system/site/build-warnings.ts:44-64`. The finding cited line 146, but the file is 64 lines.
- **What:** the scanner matches only `/^[ \t]*```(.*)$/`. The verifier ran it against `marked`: `~~~tjs` and four-backtick `tjs` both render as `language-tjs` and become live examples (`insert-examples.ts:187`), but the helper returns an empty set for both.
- **Consequence:** `needed` stays empty, `misconfigured()` is never called, and a strict build is green while those examples load tjs-lang from a CDN at run time. `site-config.ts:305-314` says a green strict build means that is absent.
- **Why now:** B1's fix routes a second gate through this helper, so its gaps then apply to both gates.
- **Fix:** track the opening fence's marker and length, and close only on a bare fence of at least that length; accept `~~~`. Add tests for `~~~tjs`, four-backtick fences, and the nested case in follow-up 2 below.
- **Not counted:** the "unreadable corpus is swallowed" half. The verifier judged it weak, because the same build parses `DOCS_JSON` at three earlier points and would likely fail first.
