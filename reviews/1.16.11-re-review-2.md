## Follow-ups to file (virta board, `project:tosijs-ui`; `TODO.md` is a pointer)

Minor:

- [ ] **(minor, verified, correctness + blast-radius, deduped) A heading and a live example can share an `example-N` id, the build is silent, and the comment and doc say the heading wins when it often does not.**
  - **Where:** `src/doc-system/heading-id.ts:41-45`, `src/live-example/insert-examples.ts:255`, `src/doc-browser.ts:1254`, `src/doc-system/site/epub.ts:348`, `src/doc-system/doc-site-system.md:1541`.
  - **Case 1, repeated "Example":** two `## Example` headings, each followed by a live example. The second heading gets `example-1`, and so does the first live example, which comes earlier in the document. `querySelector` returns the first match, so `#example-1` meant for the heading lands on the example.
  - **Case 2, "Example N" titles:** a heading "Example 2" shares its id with the page's second live example. Which one a link reaches depends on layout. The ePub's "run this live" link uses the same id and cannot be corrected after a book ships (read from code, no ePub built).
  - **Reach:** adopters only. None of the 70 docs in `demo/docs.json` produces an `example-N` heading id. In 1.16.10 headings had no ids, so adopters get this by updating.
  - **Fix:** keep the no-reservation rule; it is what ended the hang. Add a build warning, failing under `strict`, when a page has a heading id matching `example-N` and at least N live examples (`collectCodeTokens` / `liveFenceLanguages` answer the second half). Correct the class comment and the doc sentence to say first in document order wins. Alternative: have `insertExamples` skip an `example-N` id already on the page.
- [ ] **(minor, unverified: sanity-check before acting, blast-radius) Every `#example-N` link is still exempt from the dead-anchor check.** `src/doc-system/site/build-warnings.ts:114`. A page with two live examples linking `#example-7` passes `strict: true`. `doc-site-system.md` still says the build warns about any in-page link matching no id. This is the open item from `reviews/1.16.11-re-review.md`; removing the reservation fixed half of it. Fix: exempt only when the page has at least N live examples, using the same predicate as the warning above. Otherwise amend the doc sentence to name the exemption.
- [ ] **(minor, unverified, correctness) The tab-preservation change in `renderTjsTests` has no test that fails without it.** `src/live-example/component.ts:1941`. Reverting the four lines reportedly leaves every lane green. Extend `tests/example-views.pw.ts:183`: after `showInline('code')` select Docs or Console, trigger the refresh that adds "tjs tests", and assert `editors.bodies[editors.value]` is the same element.
- [ ] **(minor, unverified, blast-radius) The regression test for the hang cannot fail; a regression hangs `bun test` instead.** `src/doc-system/heading-id.test.ts:54`. The 2000 ms timeout cannot interrupt a synchronous loop; the lens reports a scratch `while (true) {}` test with a 500 ms timeout ran past 15 s on Bun 1.4.2. `ci.yml` has no `timeout-minutes`, so CI would sit until GitHub's 6 hour default. Fix: run the check in a subprocess or Worker with a kill timer, or through a helper that throws after N iterations. Add `timeout-minutes` to both CI jobs.

Nit:

- [ ] **(nit, verified as plausible from code, not reproduced, correctness) The preserved tab is read from the `hidden` attribute, which lags `editors.value` until tosi-tabs' next queued render.** `src/live-example/component.ts:1943`. If a reader picks a non-first tab and tjs results land in the same pre-paint frame, the stale index is written back and that one click is lost, once per example. The panel-just-opened path is benign. Fix: capture `editors.bodies[editors.value]` before inserting and re-select by `indexOf` after `setupTabs()`, as `syncSourceTabs` does. Worth doing in the same change as the missing test above.
