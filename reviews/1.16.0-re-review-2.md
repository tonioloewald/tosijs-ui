## Direct answer to your request ("stop prettier touching markdown")

- **tosijs-ui is already done.** Commit `3aab6f185` (2026-09-04, before this base) added `*.md` to `.prettierignore` at line 53, and `bun run format-check` follows it. The 1.16.0 diff (`c3765a5c2...HEAD`) changes nothing about prettier. It covers the `<tosi-md>` allowed-elements work, the release-notes heading regex, CHANGELOG/migrating.md, and generated output.

The follow-ups below close that gap.

## Findings by severity

### Major
1. **The prettier/markdown policy has not reached the other repos (confirmed, blast-radius, cross-cutting).** The rule gets copied into each repo by hand, and so far it has reached 3 of the 14 repos that use prettier.
   - The verifier checked each sibling. `prettier --write .` still reaches markdown in bindinator.js (34 .md files), editor2 (4), manta (1), tjs-lang (204), tosijs-3d-ensemble (25), tosijs-editor (21), tosijs-product (13), tosijs-virta (28), wobbly (10) and wordly (1).
   - loewald-dot-com only formats `src` and `functions/src`, so it is affected only if markdown lives under those paths.
   - `practices/code-quality.md:33` says it outright: "Agreed at the tosijs-ui level, but it did not propagate."
   - **tosijs-ui#187** ("Ship the house format step … so every consumer stops rediscovering it") is still OPEN.
   - This doesn't block 1.16.0 because nothing regressed. But it is the actual substance of your request, so it is the top follow-up.

### Minor
2. **`release-check` blames missing prose when the real cause is an un-bumped version (confirmed, correctness, `bin/release-notes.ts:106-125`).**
   - At HEAD, package.json is still `1.15.5`. The gate therefore checks the `## 1.15.5` section, which has already been released.
   - It prints "8 annotation(s) since v1.15.5 are not mentioned in CHANGELOG.md" and exits 1.
   - All 8 are already written up in `## 1.16.0 (unreleased)`, and `--check --version=1.16.0` exits 0.
   - Going red is correct. The diagnosis is wrong: it asks the author to write prose that already exists and never mentions the version bump. The tool ships to adopters as `tosijs-release-notes`.
   - This is not a release problem as long as the release process bumps the version first (Publishing step 1). Fix it now if it's cheap; otherwise file it.
3. **The shared practices doc contradicts itself on prettier and markdown (unverified, blast-radius, `../tosijs-coding-practices/practices/code-quality.md:28` vs `:43-44` and `:52-67`).**
   - Line 28 says "Prettier never formats markdown: `*.md` goes in `.prettierignore`".
   - Later bullets say "Don't `.prettierignore` the file", and "Turn off Prettier's *embedded* formatting for markdown, not Prettier itself".
   - An adopter who follows the later bullet keeps formatting markdown. That may be one reason the rule stalled at 3 of 14 repos.
   - The later bullet also names a real cost: prettier's bullet rewrite was the only thing detecting a wrapped line that starts with `+` or `-` and gets turned into a list. Ignoring `*.md` drops that detection, and nothing else does it now.

### Nit
4. **The `allowedElements` comment overstates array support (unverified, correctness, `src/markdown-viewer.ts:171`).**
   - Assigning an array does filter correctly, because `String()` is applied.
   - But tosijs warns on every write (tosijs#24), the value is not reflected to `allowed-elements`, and the emitted `.d.ts` types it as `string`, so arrays are a TypeScript error.
   - No adopter is affected, since the tag is unpublished.
5. **`ALWAYS_UNWRAPPED` is a hand-maintained tag list (unverified, blast-radius, `src/markdown-viewer.ts:159`).**
   - A future component that renders raw HTML or executes code, including an adopter's own, is only protected if someone remembers to edit this set.
   - Exposure is small, because it only matters if a host allowlists such a tag.
