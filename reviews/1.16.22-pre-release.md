## Completeness gaps

- **Diff basis moved:** see "Owner needs to read" item 1. `e9a7b9491` adds nothing to review, but the release-check and Playwright runs recorded on `b1097fa92` do not count for it.
- **The nav regrouping broke a Playwright spec, and nothing checked for others.** `highlight.pw.ts` failed in all three browsers after icons moved under Components (fixed in `e9a7b9491`). No lens checked other `tests/*.pw.ts` nav selectors, doc-test pages that click nav links, ePub volume order after the Appendices and parent moves, or llms.txt grouping. Re-run the full `bun playwright test` and `bun book` on HEAD.
- **`home` has no e2e coverage.** Untested in a browser: `/` serving the chosen doc, README at `/readme/`, path-routing hydration, the dev-server SPA fallback, and query/memory routing. Turning `home` on moves README from `/` to `/readme/`, which breaks inbound links and canonicals. No lens confirmed this is documented as a URL change for adopters. File it on the board.
- **The trustLan security model depends on HTTPS, and that is unstated.** `isSameOriginRequest` rules out DNS rebinding from a LAN browser only because the dev server is HTTPS-only with a cert for localhost and `<host>.local`. Write that dependency down next to the trustLan gate, so that adding a plain-HTTP listener cannot silently turn trustLan into a rebinding path.
- **The content review pass (`7a9fc9fd3`, board #3345) was not fact-checked line by line.** Specifically: the migrating.md entries for 1.16.17, 1.16.19 and 1.16.21 (iconSvg throw cases, the tjs-lang 0.14 refusal list), and the Quick Start link to `/`, which is wrong on any site that sets `home`. The user asked to de-emphasise icons now that icons.tosijs.net points at that page. No lens checked whether README or llms.txt still lead with icons or link to them as top-level.
- **Lenses that did not run:** coverage (no e2e for `home`, trustLan or `header: false` beyond page-layout.pw.ts); dx (the trustLan refusal message advertises "set trustLan: true" to anyone refused, which nudges people towards a risky opt-in; nobody judged that advice); idiom/dryness (the icon-rules.ts, icon-svg.ts and icons.ts "one owner" refactor in `6bb901ea1` was not checked for a surviving second copy of the suffix-vs-rule precedence).
- **No red tests were reported.** One `bun test` run showed 14 failures across 1759 collected tests during contention, against 1863/0 on three clean runs. Treat it as unexplained until a clean full run on HEAD confirms 1863/0.
