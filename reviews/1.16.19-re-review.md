## Fix before the tag

- [ ] **`iconSvg` throws instead of returning `undefined` for unknown camelCase names whose tail is an icon** (correctness + blast-radius, **verified**). `src/icon-svg.ts:66`.
  - **Cause.** `isComposition` accepts any capital letter at index ≥1 when the lower-cased tail (or its suffix-stripped base) names an icon. It never checks the prefix against the renderer's rules. The renderer (`composeIcon`, `src/icons.ts` ~817–868) only knows `spin` (regex), `un`, `check`, `cancel`, `search`, `add`, `remove`, `glow` and rules registered at runtime.
  - **Repro.** At HEAD, `redLock`, `fooLock`, `xLock`, `chevronDownX`, `myChevronRight`, `fooCheck`, `bigChevronDown`, `redX` and `myCloud` all throw `"… is not a single SVG … Render it with icons.<name>()"`. `icons.<name>()` then logs `icon <name> does not exist` and draws the placeholder, so the advice in the error is wrong. `lockSmith` returns `undefined`, so two names that are equally unknown behave differently.
  - **Why it matters.** 1.16.18 returned `undefined` for every one of these names. An adopter build or SSR step that does `iconSvg(name) ?? fallback` now crashes. The module doc and the CHANGELOG both say "a name nothing would draw still returns `undefined`", and that promise is half of the reason this ships as a patch.
  - **Fix.** Move the built-in rule prefixes (the strings plus the `spin` and `glow` regexes) into a DOM-free module next to `src/icon-suffixes.ts`. Seed `iconRules` in `icons.ts` from that module, and have `isComposition` test only those prefixes. Note in the doc comment that rules an adopter adds with `iconRules.push` cannot be seen without a DOM. While in there, fold away the redundant clause (the nit below).
  - **Check that clears it.** Add `expect(iconSvg('redLock')).toBeUndefined()`, plus the same for `fooCheck`, `chevronDownX` and `myCloud`, to the "nothing would draw" block in `src/icon-svg.test.ts`. Those assertions must fail with the fix reverted. Also keep `unLock` / `spinLoader` throwing (real rules). No re-review is needed.
  - **If the maintainer wants to keep the heuristic,** record that decision, then change the CHANGELOG, the doc comment and the error text to say that look-alike names throw.
