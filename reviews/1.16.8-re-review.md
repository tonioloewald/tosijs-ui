## Findings

All are minor unless marked. Correctness comes first.

**F1 (verified, regression in the remediation). Off-localhost, enabling tests after navigating records a false failure against the landing page.** `src/doc-browser.ts:2452`
- The non-localhost branch of `startBackgroundTests` uses the construction-time `const currentDoc` (line 684), not `app.currentDoc`.
- `settleCurrentPage` then calls `closePage(undefined, …)`, which fabricates "The page finished but reported no tests" for a page that was never run.
- Mirror case: land on a page without tests, navigate to one with tests, enable. It resolves `pagesWithTests: 0` and never settles the page showing.
- Before this diff the same stale variable only fed a timer and recorded nothing.
- It is a false red (fail-closed), on an opt-in path, with a caveat: a landing page with a test-only example returns its existing tally instead.
- This is the maintainer's own over-the-tunnel path, and the fix is to read `app.currentDoc` at call time. **Recommend fixing before tagging.** If fixed, re-review scope is correctness + blast-radius over that diff only.

**F2 (verified). The per-example tally never drops detached examples.** `src/doc-browser.ts:804`
- `liveResults` resets only when a `testcomplete` arrives for a different filename.
- Going A → page without tests → A multiplies counts (the lens measured 11 → 22 → 33; the verifier confirmed the mechanism by code trace, not by re-running the probe).
- A failure from a detached example keeps the page red after its replacement passes.
- The comment at lines 800-802 is false for this case.
- It affects the reader-facing widget only. The gate resolves before any navigation.

**F3 (verified). The CI doc-test gate is a second copy of the pass/fail rule, and the two already disagree.** `tests/doc-tests.pw.ts:105`
- The spec never calls `testReportVerdict`. It still asserts `.toBe(pagesWithTests)` where the shipped rule was relaxed to `<`.
- It asserts the count before the failure-detail block, so the "20 of 19" case reports a count mismatch instead of naming the failed test.
- The CI copy is stricter everywhere, so there is no false green.
- Prior-review F10 is marked fixed, but only the export happened. No keep-decision is recorded.
- Not checked: whether a page without test blocks can record a passing entry. If it can, CI would fail a run the shipped rule accepts.

**F4 (verified). "One way to add up a page for all three paths" is not true of the iframe path.** `src/doc-browser.ts:2366`
- `messageHandler` still does `tests.push` / `+=` by hand, with no per-example de-duplication.
- Only the in-place path uses `tallyExamples`. Closing is shared; adding up is not.
- Both paths write `pageTestResults[filename]`, so navigating in place mid-run can double or replace an entry. The verifier judged this real but narrower than the lens stated.
- The header comment in `test-completion.ts` and the commit subject overstate the unification.

**F5 (unverified; merges two findings from correctness and blast-radius). Navigating away during the localhost background run makes the starting page's verdict depend on timing.** `src/doc-browser.ts:866-868`
- If some examples had reported, the partial tally passes, which is a fail-open shape.
- If none had, a false "reported no tests" failure is recorded, and the dev server prints a loud `❌ Browser tests` during a plain `bun start` for every `tosijs-ui/site` adopter.
- The host/iframe double-write here is the same one as in F4.
- Interactive only; no lane navigates mid-run. Sanity-check before acting.

**F6 (unverified). Stalled examples are described differently in place and via iframe.** `src/doc-browser.ts:866`
- The in-place failure is one aggregate line at 45s with no source snippet.
- The iframe failure is one per example, with the first 120 characters of source, at 30s.
- This also makes the new Playwright name-equality comparison fail for a shape reason whenever a stall occurs.

**F7 (unverified). Two behaviour changes have no test that fails without them.** `src/doc-browser.ts:2369`, `2411`; `src/doc-system/site/dev-server.ts:1323`, `2824`
- (a) The `event.source !== testFrame.contentWindow` filters. The CHANGELOG lists these as a fix.
- (b) `handleTestReport`'s incomplete-report print and the widened `!verdict.ok` branch.
- This is a missing-test item, so it never blocks.

**F8 (unverified). `testReportVerdict` reaches adopters only through a CHANGELOG line.** `src/doc-system/doc-site-system.md`
- No published page documents the `__docTestResults` shape, or why `failed === 0` is not a pass.
- Adopters with their own gate stay fail-open until they read the release notes.

**F9 (unverified, nit). `testReportVerdict` no longer notices an over-count.** `src/doc-system/site/test-report.ts:38`
- One extra entry can stand in for a missing page-with-tests. The lens says this is not currently reachable as a false pass.
- Off-localhost, toggling tests re-enters `settleCurrentPage` and inflates `pagesTested`. This shape pre-dates the diff.
