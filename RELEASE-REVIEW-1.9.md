## BLOCKERS (all verified — must fix before tagging 1.9.0)

### B1. The tunnelled-workspace READ gate keys on `X-Forwarded-*`, not on the listener — fails open

`src/doc-system/site/dev-server.ts:976-981`

```ts
const viaProxy = request.headers.get('x-forwarded-for') !== null ||
                 request.headers.get('x-forwarded-host') !== null
const lockedDown = config.preview?.tunnel?.requireToken !== false
if (lockedDown && viaProxy && !linkToken) { … 401 … }
```

`viaTunnel` — the unforgeable listener signal — is a parameter of the same closure (line 927) and is used correctly by _every other_ gate in the file (`/report` 1063, `mayWriteSource` 1101, `/__devlink` 1129, and even `statusSnippet` 523, which guards a strictly lower-stakes disclosure). Any forwarder that does not set `X-Forwarded-*` — `ssh -R` with `GatewayPorts yes`, `ngrok tcp`, `socat`, iptables DNAT, bare nginx `proxy_pass`, HAProxy without `option forwardfor`; the exact list `dev-auth.ts:171-189` enumerates as the reason the _write_ path was moved off headers — arrives with `viaProxy === false` and reads the entire uncommitted working tree unauthenticated, while `requireToken` (default `true`) promises "no session, nothing at all — not even the page".

This is invisible to testing because the blessed path is Caddy `reverse_proxy`, which sets XFF by default. Writes remain gated; reads do not.

**Fix:** `if (lockedDown && (viaTunnel || isProxiedRequest(request.headers)) && !linkToken)` — which also uses the already-imported helper and clears one of the three lint errors. Add a `dev-auth`/handler test: tunnel listener + no forwarding headers + no session → 401.

### B2. `?t=` is intercepted on every request, every method, on every adopter's dev server — and the CHANGELOG claims a fix that was never written

`src/doc-system/site/dev-server.ts:959, 1004` (and the shipped `dist/doc-system/site/dev-server.js:817, 857`)

`CHANGELOG.md:104` states: _"`?t=` is only intercepted when a tunnel is configured, and only on GET — `t` is the classic cache-buster name, and a 302'd POST loses its body."_ Neither guard exists. `const linkToken = reqUrl.searchParams.get(LINK_PARAM)` runs at the top of `handleRequest` with no `config.preview?.tunnel` check and no method check, for both listeners.

Reproduced live: on a plain `bun start` with no preview config, `GET /?t=12345` → **401 "That invite link has been used"** in place of the page; `POST /path?t=1` → 401, request lost. Commit `52286147` asserts the gate ("Now gated on `preview.tunnel` and GET") but `--name-only` shows it never touched `dev-server.ts`. The in-file doc comment ("An invalid or already-spent token is not an error — it just falls through unauthenticated") is also now false.

**Fix:** `const linkToken = config.preview?.tunnel && request.method === 'GET' ? reqUrl.searchParams.get(LINK_PARAM) : null`, plus a regression test that `?t=garbage` on a tunnel-less config routes normally. Then **re-verify every other fix claimed in the beta/rc notes against the code** — two of the claims audited here (this and the `remotePort` derivation, M2) are absent.

### B3. `isSafeRemotePath` accepts the preview ROOT itself → `rsync --delete` over the whole shared box

`bin/resolve-site-config.ts:123`

```ts
return SAFE_ROOTS.some((root) => norm === root || norm.startsWith(root + '/'))
```

`isSafeRemotePath('/srv/preview')` returns **true** (verified by running it). `preview: { path: '/srv/preview' }` — or `--path=/srv/preview`, i.e. forgetting the project segment — then runs `rsync -az --delete docs/ host:/srv/preview/`, deleting every other project's directory, `_index`, and all of `/srv/preview/_sites/*.caddy`, the single source of truth the Caddyfile glob-imports. `registerSite()` then runs `systemctl reload caddy` in the same command, so every other preview loses its route immediately. `bin/deploy-preview.ts:78` is the only guard. The error text already advertises the sub-path invariant it fails to enforce, and `dev-auth.test.ts:233-262` does not pin the bare-root case, so tightening breaks nothing.

**Fix:** `SAFE_ROOTS.some((root) => norm !== root && norm.startsWith(root + '/'))` + a test pinning that `/srv/preview` itself is refused.
